Bamboo Board 코드 주석과 해설 샘플
====================================

이 파일의 목적
-------------

이 문서는 디자인이나 페이지 수를 맞추지 않은 순수 텍스트 설명입니다.
실제 프로젝트의 원본 코드는 수정하지 않았으며, 설명용으로 복사한 코드에만 주석을 추가했습니다.

이번 샘플에서 다루는 세 가지 코드는 다음과 같습니다.

1. React에서 게시글 작성 폼을 제출하는 코드
2. Spring Controller가 요청을 받고 Service가 게시글을 저장하는 코드
3. JUnit으로 Post 객체의 초기 상태를 검사하는 테스트 코드

설명 원칙
---------

- 처음 등장하는 문법은 자세히 설명합니다.
- 같은 문법이 다시 나오면 실행 흐름만 설명합니다.
- 메서드 이름을 단순히 한국어로 번역하는 데서 끝내지 않습니다.
- 해당 메서드의 입력값, 반환값, 다음 메서드와 연결되는 방식까지 설명합니다.
- assertThat(...).isFalse() 같은 체인 형태의 코드도 중간 결과를 나눠서 설명합니다.


========================================================================
코드 1. React에서 게시글 작성 폼 제출하기
========================================================================

실제 파일
---------

frontend/src/components/posts/PostEditor.jsx

이 함수의 역할
--------------

사용자가 게시글 작성 화면에서 "완료" 버튼을 누르면 handleSubmit 함수가 실행됩니다.
이 함수는 다음 순서로 일합니다.

입력값의 앞뒤 공백 제거
→ 제목과 내용이 비었는지 검사
→ 이미지 파일이 올바른지 검사
→ 이미지 파일을 Data URL 문자열로 변환
→ 제목, 내용, 이미지로 요청 객체 생성
→ 부모 컴포넌트가 전달한 onSubmit 함수 호출
→ 성공 또는 실패와 관계없이 제출 중 상태 해제


[주석을 자세히 추가한 코드]

async function handleSubmit(event) {
    // async:
    // 이 함수 안에서 await를 사용할 수 있다는 뜻입니다.
    // 이미지 변환이나 서버 요청처럼 시간이 걸리는 작업을 기다릴 수 있습니다.
    //
    // event:
    // 폼 제출 사건에 관한 정보가 들어 있는 객체입니다.
    // 브라우저가 React의 이벤트 함수에 자동으로 전달합니다.

    event.preventDefault();
    // HTML의 form은 원래 제출되면 페이지를 새로 불러오려고 합니다.
    // preventDefault()는 그 기본 동작을 막습니다.
    // 이제 페이지를 새로고침하지 않고 React 코드가 제출 과정을 처리합니다.

    const title = form.title.trim();
    // const:
    // 새로운 변수를 선언합니다.
    // title이라는 변수에 다른 값을 다시 대입할 수 없다는 뜻입니다.
    //
    // form.title:
    // form 객체의 title 속성에 들어 있는 문자열을 읽습니다.
    //
    // trim():
    // 문자열 앞뒤의 공백을 제거한 새 문자열을 반환합니다.
    // 예: "  안녕하세요  ".trim()의 결과는 "안녕하세요"입니다.
    // 원래 form.title을 직접 변경하는 것은 아닙니다.

    const content = form.content.trim();
    // 위의 title 처리와 같은 흐름입니다.
    // 반복되는 문법이므로 이후에는 "내용의 앞뒤 공백을 제거한다"라고만 설명합니다.

    const imageError = getPostImageFilesError(files);
    // getPostImageFilesError:
    // 프로젝트에서 직접 만든 함수입니다.
    // files 배열에 이미지 개수, 크기, 확장자 문제가 있는지 검사합니다.
    //
    // 반환값:
    // 문제가 있으면 오류 문구가 담긴 문자열을 반환합니다.
    // 문제가 없으면 빈 값(null 등)을 반환합니다.

    if (!title || !content) {
        // if (조건):
        // 괄호 안의 조건이 true일 때 중괄호 안의 코드를 실행합니다.
        //
        // !title:
        // !는 논리 부정 연산자입니다.
        // title이 빈 문자열 ""이면 거짓으로 취급되므로 !title은 true가 됩니다.
        //
        // ||:
        // OR 연산자입니다.
        // 왼쪽 또는 오른쪽 중 하나만 true여도 전체 조건은 true입니다.
        //
        // 따라서 이 조건은 "제목 또는 내용 중 하나라도 비어 있는가?"라는 뜻입니다.

        setError("*글 제목과 이야기 내용을 모두 작성해주세요.");
        // setError는 React의 상태 변경 함수입니다.
        // error 상태를 이 문자열로 바꾸고 React가 오류 문구가 보이도록 다시 렌더링합니다.

        return;
        // 값을 반환하지 않고 현재 함수를 즉시 끝냅니다.
        // 따라서 아래의 이미지 변환과 onSubmit 호출은 실행되지 않습니다.
    }

    if (imageError) {
        // imageError에 오류 문자열이 들어 있다면 true로 취급됩니다.

        setError(`*${imageError}`);
        // `...`는 템플릿 리터럴입니다.
        // ${imageError} 위치에 imageError 변수의 실제 값이 들어갑니다.
        //
        // 예:
        // imageError가 "이미지는 3개까지만 첨부할 수 있습니다."라면
        // 최종 문자열은 "*이미지는 3개까지만 첨부할 수 있습니다."가 됩니다.

        return;
        // 이미지가 잘못되었으므로 서버 요청 전에 함수를 끝냅니다.
    }

    try {
        // try 블록에는 실패할 가능성이 있는 코드를 작성합니다.
        // 이미지 변환이나 서버 요청 중 예외가 발생하면 실행이 catch 블록으로 이동합니다.

        setIsSubmitting(true);
        // 제출 중 상태를 true로 변경합니다.
        // 화면에서는 이 값을 이용해 버튼을 비활성화하고 "처리 중" 문구를 표시합니다.
        // 사용자가 버튼을 연속으로 누르는 것도 방지합니다.

        setError("");
        // 이전에 화면에 표시된 오류 메시지를 빈 문자열로 초기화합니다.

        const imageFiles = files.length
            ? await Promise.all(files.map(fileToDataUrl))
            : initialValues?.imageUrls ?? [];
        // 이 부분은 여러 문법이 한 표현식에 들어 있으므로 나눠서 읽어야 합니다.
        //
        // 1) files.length
        //    files 배열에 들어 있는 원소 개수입니다.
        //    0이면 거짓, 1 이상이면 참으로 취급됩니다.
        //
        // 2) 조건 ? A : B
        //    삼항 연산자입니다.
        //    조건이 참이면 ? 뒤의 A를 선택하고, 거짓이면 : 뒤의 B를 선택합니다.
        //
        // 3) files.map(fileToDataUrl)
        //    files의 각 이미지 파일에 fileToDataUrl 함수를 실행합니다.
        //    map은 실행 결과들로 새로운 배열을 만듭니다.
        //    fileToDataUrl은 비동기 함수이므로 결과 배열에는 Promise들이 들어갑니다.
        //
        // 4) Promise.all(...)
        //    배열에 들어 있는 모든 비동기 작업이 끝날 때까지 기다리는 Promise를 만듭니다.
        //    모든 작업이 성공하면 변환된 Data URL 문자열 배열을 결과로 줍니다.
        //    하나라도 실패하면 Promise.all 전체가 실패하고 catch로 이동합니다.
        //
        // 5) await
        //    Promise.all이 끝날 때까지 이 함수의 다음 줄 실행을 기다립니다.
        //    기다리는 동안 브라우저 전체가 멈추는 것은 아닙니다.
        //
        // 6) initialValues?.imageUrls
        //    ?.는 옵셔널 체이닝입니다.
        //    initialValues가 null 또는 undefined이면 오류를 내지 않고 undefined를 만듭니다.
        //    initialValues가 존재하면 그 안의 imageUrls를 읽습니다.
        //
        // 7) 값1 ?? 값2
        //    왼쪽 값이 null 또는 undefined일 때만 오른쪽 값을 사용합니다.
        //    따라서 기존 이미지 목록도 없다면 마지막의 빈 배열 []을 사용합니다.

        await onSubmit({
            title,
            content,
            imageFiles,
        });
        // onSubmit:
        // PostEditor를 사용하는 부모 컴포넌트가 Props로 전달한 함수입니다.
        //
        // { title, content, imageFiles }:
        // JavaScript 객체를 만드는 문법입니다.
        // 속성명과 변수명이 같기 때문에 아래 코드의 축약형입니다.
        //
        // {
        //     title: title,
        //     content: content,
        //     imageFiles: imageFiles
        // }
        //
        // await:
        // 부모의 onSubmit 함수가 서버 요청을 끝낼 때까지 기다립니다.
        // 서버 요청이 실패하면 아래 catch 블록으로 이동합니다.
    } catch (submitError) {
        // try 안에서 예외가 발생하면 실행됩니다.
        // submitError에는 발생한 Error 객체가 들어옵니다.

        setError(
            `*${getErrorMessage(
                submitError,
                "요청 처리에 실패했습니다.",
            )}`,
        );
        // getErrorMessage는 서버 오류 객체에서 사용자에게 보여줄 문구를 꺼냅니다.
        // 알맞은 문구가 없으면 두 번째 인자인 기본 문구를 사용합니다.
        // 얻은 문구 앞에는 템플릿 리터럴을 이용해 *를 붙입니다.
    } finally {
        // finally는 성공하든 실패하든 마지막에 반드시 실행됩니다.

        setIsSubmitting(false);
        // 제출 중 상태를 해제합니다.
        // 성공했을 때도 실행되고 catch에서 오류를 처리한 뒤에도 실행됩니다.
    }
}


[실행 흐름을 실제 값으로 따라가기]

사용자가 다음 값을 입력했다고 가정합니다.

제목: "  오늘 있었던 일  "
내용: "안녕하세요"
첨부 파일: 2개

1. preventDefault()가 페이지 새로고침을 막습니다.
2. trim() 결과로 title은 "오늘 있었던 일"이 됩니다.
3. 제목과 내용이 모두 있으므로 첫 번째 if를 통과합니다.
4. 이미지가 올바르면 두 번째 if도 통과합니다.
5. setIsSubmitting(true)로 버튼을 잠급니다.
6. map이 두 이미지 각각에 fileToDataUrl을 호출합니다.
7. Promise.all이 두 이미지 변환이 모두 끝날 때까지 기다립니다.
8. onSubmit에 다음 형태의 객체를 전달합니다.

{
    title: "오늘 있었던 일",
    content: "안녕하세요",
    imageFiles: ["data:image/...", "data:image/..."]
}

9. 부모 컴포넌트가 이 객체를 서버로 전송합니다.
10. 마지막에 finally가 실행되어 제출 중 상태를 해제합니다.

실제 파일

backend/src/main/java/kr/adapterz/springdatajpa/service/PostService.java

이 코드를 하나로 묶은 이유
------------------------

Controller의 createPost는 HTTP 요청을 Java 객체로 바꾸고 로그인 사용자를 찾습니다.
그 후 실제 게시글 생성 규칙을 Service의 createPost에 넘깁니다.
따라서 두 메서드는 서로 다른 파일에 있지만 하나의 요청 흐름으로 읽어야 합니다.


[2-A. Controller 코드에 자세한 주석 추가]

@RestController
// @로 시작하는 것은 Java의 어노테이션입니다.
// 어노테이션은 클래스나 메서드에 추가 정보를 붙입니다.
//
// @RestController는 이 클래스가 HTTP 요청을 받는 Controller임을 Spring에 알립니다.
// 메서드가 반환한 Java 객체는 JSON 응답으로 변환됩니다.

@RequestMapping("/posts")
// 이 Controller에서 처리할 공통 URL 앞부분을 "/posts"로 정합니다.
// 아래 @PostMapping에 별도 경로가 없으므로 최종 주소는 POST /posts가 됩니다.

@RequiredArgsConstructor
// Lombok이 final 필드를 매개변수로 받는 생성자를 자동 생성합니다.
//
// 아래의 private final PostService postService를 생성자로 전달받게 됩니다.
// Spring은 생성자를 통해 실제 PostService 객체를 넣어줍니다.
// 이것을 생성자 주입 또는 의존성 주입이라고 합니다.

public class PostController {
    // public:
    // 다른 클래스와 Spring 프레임워크가 이 클래스를 사용할 수 있습니다.
    //
    // class:
    // 관련된 필드와 메서드를 하나로 묶는 설계 단위입니다.
    //
    // PostController:
    // 클래스 이름입니다.

    private final PostService postService;
    // private:
    // 이 필드는 PostController 내부에서만 직접 접근할 수 있습니다.
    //
    // final:
    // 생성자에서 한 번 받은 뒤 다른 PostService 객체로 바꿀 수 없습니다.
    //
    // PostService:
    // 필드에 저장할 객체의 자료형입니다.
    //
    // postService:
    // 이 필드의 이름입니다.

    @PostMapping
    // POST /posts 요청이 들어오면 바로 아래 createPost 메서드를 실행합니다.

    @ResponseStatus(HttpStatus.CREATED)
    // 요청이 성공했을 때 HTTP 상태 코드를 201 Created로 응답하도록 지정합니다.
    // 게시글처럼 새로운 자원을 생성한 경우 사용하는 상태 코드입니다.

    public PostResponseDto createPost(
            @AuthenticationPrincipal CustomUserDetails userDetails,
            @Valid @RequestBody PostRequestDto request
    ) {
        // public:
        // Spring이 이 메서드를 호출할 수 있습니다.
        //
        // PostResponseDto:
        // 이 메서드가 최종적으로 반환해야 하는 값의 자료형입니다.
        //
        // createPost:
        // 메서드 이름입니다.
        //
        // 메서드 괄호 안에는 두 개의 매개변수가 있습니다.

        // @AuthenticationPrincipal:
        // Spring Security가 현재 인증된 사용자를 찾아 userDetails에 넣습니다.
        //
        // CustomUserDetails:
        // 로그인 사용자 정보를 담는 프로젝트의 클래스입니다.
        //
        // userDetails:
        // 현재 로그인 사용자를 가리키는 지역 변수 이름입니다.

        // @RequestBody:
        // HTTP 요청 본문에 들어 있는 JSON을 PostRequestDto 객체로 변환합니다.
        //
        // 예를 들어 다음 JSON이 요청으로 왔다면
        //
        // {
        //   "title": "제목",
        //   "content": "내용",
        //   "imageFiles": []
        // }
        //
        // request.getTitle()은 "제목"을 반환하게 됩니다.

        // @Valid:
        // PostRequestDto 필드에 붙은 검증 어노테이션을 실행합니다.
        //
        // @NotBlank가 붙은 title과 content는 null, 빈 문자열, 공백만 있는 문자열이면 안 됩니다.
        // @Size(max = 26)가 붙은 title은 최대 26자여야 합니다.
        // 검증이 실패하면 Service를 호출하지 않고 예외 처리 흐름으로 이동합니다.

        return postService.createPost(
                userDetails.getUserId(),
                request
        );
        // userDetails.getUserId():
        // 현재 로그인 사용자의 ID를 Long 값으로 꺼냅니다.
        //
        // postService.createPost(...):
        // 로그인 사용자 ID와 요청 DTO를 Service에 전달합니다.
        //
        // Service가 반환한 PostResponseDto를 return으로 Controller 호출자에게 돌려줍니다.
        // @RestController의 작용으로 이 객체는 JSON HTTP 응답이 됩니다.
    }
}


[2-B. Service 코드에 자세한 주석 추가]

@Service
// 이 클래스가 비즈니스 로직을 담당하는 Service임을 Spring에 알립니다.
// Spring이 PostService 객체를 생성하고 필요한 Controller에 주입합니다.

@RequiredArgsConstructor
// final Repository 필드들을 매개변수로 받는 생성자를 Lombok이 생성합니다.

@Transactional(readOnly = true)
// 클래스의 기본 트랜잭션을 읽기 전용으로 설정합니다.
// 조회 메서드는 기본적으로 이 설정을 사용합니다.
// 데이터를 변경하는 메서드는 아래처럼 별도의 @Transactional을 붙여 덮어씁니다.

public class PostService {

    private final PostRepository postRepository;
    // Post 엔티티를 데이터베이스에 저장하고 조회하는 Repository입니다.

    private final UserRepository userRepository;
    // User 엔티티를 조회하는 Repository입니다.

    @Transactional
    // 게시글과 이미지 저장을 하나의 작업 단위로 묶습니다.
    //
    // 처리 도중 예외가 발생하면 트랜잭션을 롤백할 수 있습니다.
    // 즉, 게시글만 저장되고 이미지는 저장되지 않는 식의 불완전한 상태를 막습니다.
    //
    // readOnly를 적지 않았으므로 기본값 false가 적용되어 데이터를 변경할 수 있습니다.

    public PostResponseDto createPost(
            Long loginUserId,
            PostRequestDto request
    ) {
        // Long:
        // 정수형 ID를 객체로 표현하는 Java 자료형입니다.
        // 기본형 long과 달리 null을 가질 수 있습니다.
        //
        // loginUserId:
        // Controller가 전달한 로그인 사용자의 ID입니다.
        //
        // request:
        // 요청 JSON에서 만들어진 PostRequestDto 객체입니다.

        ImageDataUrlValidator.validatePostImages(
                request.getImageFiles()
        );
        // request.getImageFiles():
        // DTO가 가지고 있는 이미지 문자열 목록을 반환합니다.
        // 반환 자료형은 List<String>입니다.
        //
        // ImageDataUrlValidator.validatePostImages(...):
        // 이미지 개수와 Data URL 형식 등이 올바른지 검사합니다.
        // 올바르면 별도 반환값 없이 다음 줄로 진행합니다.
        // 올바르지 않으면 예외를 던지고 메서드 실행이 중단됩니다.

        PostResponseDto postResponseDto = new PostResponseDto();
        // PostResponseDto:
        // 생성 성공 결과를 담는 응답 객체의 자료형입니다.
        //
        // postResponseDto:
        // 생성된 객체를 가리키는 지역 변수입니다.
        //
        // new:
        // 메모리에 새로운 객체를 생성할 때 사용하는 키워드입니다.
        //
        // PostResponseDto():
        // 매개변수가 없는 생성자를 호출합니다.
        // 이 DTO의 message 필드는 기본값 "post_success"를 갖습니다.

        User user = getLoginUser(loginUserId);
        // getLoginUser는 PostService 내부의 private 메서드입니다.
        // userRepository에서 삭제되지 않은 사용자를 찾습니다.
        //
        // 사용자가 존재하면 User 객체를 반환합니다.
        // 사용자가 없다면 AuthException("No_User")을 던집니다.
        //
        // 반환된 User 객체를 user 변수에 저장합니다.

        Post post = new Post(
                user,
                request.getTitle(),
                request.getContent()
        );
        // new Post(...):
        // Post 클래스의 생성자를 호출해 새로운 게시글 객체를 만듭니다.
        //
        // 첫 번째 인자 user:
        // 게시글 작성자입니다.
        //
        // 두 번째 인자 request.getTitle():
        // 요청 DTO에서 제목 문자열을 꺼냅니다.
        //
        // 세 번째 인자 request.getContent():
        // 요청 DTO에서 본문 문자열을 꺼냅니다.
        //
        // Post 생성자 안에서는 다음과 같은 기본값도 설정합니다.
        //
        // isFixed = false
        // likeCount = 0
        // reportCount = 0
        // replyCount = 0
        // viewCount = 0
        // createdAt = 현재 시간
        // deleted = false

        post.replaceImages(request.getImageFiles());
        // 요청의 이미지 문자열 목록으로 Post의 이미지 목록을 교체합니다.
        //
        // replaceImages 안에서는 먼저 기존 postImages를 clear()로 비웁니다.
        // 그 뒤 반복문을 실행해 각 이미지마다 PostImage 객체를 만듭니다.
        // 만들어진 PostImage는 postImages 리스트에 추가됩니다.

        postRepository.save(post);
        // PostRepository의 save 메서드에 Post 객체를 전달합니다.
        //
        // Post에는 @Entity가 붙어 있으므로 JPA가 데이터베이스 엔티티로 관리합니다.
        // 새로운 Post이므로 최종적으로 posts 테이블에 INSERT가 실행됩니다.
        //
        // Post.postImages 관계에는 cascade = CascadeType.ALL이 설정되어 있습니다.
        // 따라서 Post와 연결된 새 PostImage들도 함께 저장됩니다.
        //
        // 실제 SQL은 save를 호출한 그 순간이 아니라
        // 트랜잭션이 끝나면서 flush될 때 실행될 수도 있습니다.

        return postResponseDto;
        // 생성 성공 메시지가 들어 있는 DTO를 Controller에 반환합니다.
        // Controller는 이 객체를 JSON 응답으로 변환합니다.
    }
}


[Controller부터 DB까지 한 줄씩 연결]

1. 브라우저가 POST /posts로 JSON을 보냅니다.
2. @PostMapping이 PostController.createPost를 선택합니다.
3. @RequestBody가 JSON을 PostRequestDto로 변환합니다.
4. @Valid가 제목과 내용을 검사합니다.
5. @AuthenticationPrincipal이 로그인 사용자 정보를 제공합니다.
6. Controller가 사용자 ID와 DTO를 PostService.createPost에 넘깁니다.
7. Service가 이미지 형식을 검사합니다.
8. Service가 삭제되지 않은 User를 조회합니다.
9. new Post(...)가 메모리에 게시글 객체를 생성합니다.
10. replaceImages가 이미지 엔티티들을 게시글과 연결합니다.
11. postRepository.save(post)가 JPA에 저장을 요청합니다.
12. 트랜잭션이 정상 종료되면 Post와 PostImage가 DB에 반영됩니다.
13. PostResponseDto가 Controller를 거쳐 JSON 응답으로 전달됩니다.

[assertThat 체인을 일반 문장으로 바꾸기]

assertThat(post.isDeleted()).isFalse();

위 코드를 기계적으로 왼쪽부터 읽으면 이해하기 어렵습니다.
다음 순서로 나누면 됩니다.

1. post.isDeleted()
   실제 값을 얻습니다.
   결과 예: false

2. assertThat(false)
   false를 검증할 수 있는 AssertJ 객체로 감쌉니다.

3. .isFalse()
   감싼 실제 값이 false인지 확인합니다.

일반 문장:
"post의 삭제 여부를 가져와서, 그 값이 false인지 확인한다."


[isFalse와 assertFalse의 차이]

AssertJ 방식:

assertThat(post.isDeleted()).isFalse();

JUnit 방식:

assertFalse(post.isDeleted());

두 코드는 모두 실제 값이 false인지 검사합니다.

이 프로젝트에서 사용한 AssertJ 방식은 메서드를 연속해서 연결할 수 있다는 장점이 있습니다.

assertThat(list)
        .isNotNull()
        .isNotEmpty()
        .hasSize(3);

위 코드는 같은 list에 대해 null이 아닌지, 비어 있지 않은지, 크기가 3인지 순서대로 검사합니다.
이처럼 메서드 호출 결과에 다시 점을 찍어 다음 메서드를 호출하는 것을 메서드 체이닝이라고 합니다.


[테스트가 실패하는 예]

만약 Post 생성자가 실수로 다음처럼 작성되었다고 가정합니다.

this.deleted = true;

그러면 테스트 실행 시 다음 검증의 실제 값은 true가 됩니다.

assertThat(post.isDeleted()).isFalse();

기대값은 false인데 실제 값은 true이므로 AssertionError가 발생합니다.
이 테스트 덕분에 "새 게시글이 처음부터 삭제 상태가 되는 문제"를 바로 발견할 수 있습니다.

- 새로운 어노테이션, 메서드 체인, 람다, 제네릭, JPA 관계가 나오면 다시 자세히 설명합니다.
- 단순 DTO가 반복되면 모든 파일을 싣지 않고 필드와 검증 조건의 차이만 정리합니다.
- 비슷한 Controller 메서드는 HTTP 메서드, URL, 요청 DTO, 응답 DTO의 차이만 정리합니다.
- 테스트는 성공 조건과 실패 조건이 무엇인지, mock과 when과 verify가 무엇인지 각각 최초 등장 시 자세히 설명합니다.
