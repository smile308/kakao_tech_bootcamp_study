# 15. 프론트 게시글 상세·작성/수정·댓글·회원정보

## 15.1 이 문서의 범위와 읽는 순서

14번에서 목록 화면이 `postApi.getPosts()`로 페이지를 요청하고 목록 항목을 클릭하는 지점까지 확인했습니다. 이번 문서는 그 클릭 이후의 상세 화면부터, 상세 화면에서 발생하는 좋아요·신고·삭제·댓글, 작성/수정 화면, 회원정보와 비밀번호 변경까지 연결합니다.

```text
목록의 게시글 클릭
→ AppRoutes가 /posts/:postId에 PostDetailPage를 렌더링
→ PostDetailPage useEffect가 postApi.getPost(postId)를 호출
→ api.js가 access token을 붙여 GET /posts/{postId} 전송
→ PostController → PostService.getPostView
→ 게시글·댓글·좋아요 여부·신고 여부·본인 여부·조회수 생성
→ PostDetailPage state에 post/comments 저장
→ PostDetailCard와 CommentSection 렌더링
→ 좋아요/신고/삭제/댓글 이벤트는 다시 postApi를 호출
→ 응답을 부모 state에 반영하거나 목록/로그인 화면으로 이동

작성: PostCreatePage → PostEditor → 파일 검증/Data URL 변환 → POST /posts → /posts 이동
수정: PostEditPage GET → PostEditor initialValues → PATCH /posts/{postId} → 상세 이동
회원정보: ProfileEditPage GET /users/me → ProfileEditForm → PATCH /users → 성공 toast
비밀번호: PasswordEditPage 검증 → PATCH /users/password → access token 제거 → /login 이동
```

이번 문서에서 전체 원문을 새로 확인하는 파일은 21개입니다.

- 게시글 상세: `PostDetailPage.jsx`, `PostDetailCard.jsx`, `PostImageGallery.jsx`, `PostLikeButton.jsx`, `PostReportButton.jsx`, `AuthorSummary.jsx`, `PostMetricCard.jsx`
- 댓글: `CommentSection.jsx`, `CommentEditor.jsx`, `CommentList.jsx`, `CommentItem.jsx`
- 작성/수정: `PostCreatePage.jsx`, `PostEditPage.jsx`, `PostEditor.jsx`, `PostImagePicker.jsx`
- 회원정보: `ProfileEditPage.jsx`, `ProfileEditForm.jsx`, `InfoBanner.jsx`, `Toast.jsx`
- 비밀번호: `PasswordEditPage.jsx`, `PasswordEditForm.jsx`

`api.js`, `postApi.js`, `userApi.js`, `ConfirmModal.jsx`, `ProfileImagePicker.jsx`, `ErrorView.jsx`, `PageLayout.jsx`, `errorMessage.js`, `file.js`, `validation.js`는 앞 문서에서 전체 원문을 확인했습니다. 이번 문서에서는 이 파일들이 어느 줄에서 호출되고 반환값이 어디로 들어오는지만 다시 연결합니다.

## 15.2 백엔드 계약을 먼저 확인하는 이유

프론트의 `post.isMine`, `post.comments`, `post.version`, `comment.isMine`, `user.nickname`은 프론트가 임의로 만든 값이 아닙니다. 실제 Controller와 Service가 만든 JSON field이므로, 화면 코드를 읽기 전에 서버 경계를 확인해야 합니다.

```java
@GetMapping("/{postId}") // GET /posts/{postId} 요청을 상세 조회 메서드에 연결한다.
public PostViewResponseDto getPostView(
        @PathVariable("postId") Long postId, // URL의 {postId} 문자열을 Long 매개변수로 변환한다.
        @AuthenticationPrincipal CustomUserDetails userDetails // JWT Filter가 SecurityContext에 저장한 사용자다.
) {
    return postService.getPostView(postId, userDetails.getUserId()); // Controller는 ID를 Service에 전달하고 DTO를 HTTP body로 반환한다.
}

@PatchMapping("/{postId}") // 수정 요청을 PATCH /posts/{postId}에 연결한다.
public PostFixResponseDto fixPost(
        @PathVariable("postId") Long postId, // 어느 게시글인지 URL에서 가져온다.
        @AuthenticationPrincipal CustomUserDetails userDetails, // 수정 권한을 확인할 로그인 사용자다.
        @Valid @RequestBody PostFixRequestDto request // JSON body를 DTO로 역직렬화하고 Bean Validation을 실행한다.
){
    return postService.fixPost(postId, userDetails.getUserId(), request); // 실제 권한·version·이미지 검사는 Service가 담당한다.
}

@DeleteMapping("/{postId}") // DELETE /posts/{postId} 요청을 삭제 메서드에 연결한다.
@ResponseStatus(HttpStatus.NO_CONTENT) // 성공 시 상태 코드를 204로 설정한다.
public PostDeleteResponseDto deletePost(
        @PathVariable("postId") Long postId, // 삭제 대상 게시글 ID다.
        @AuthenticationPrincipal CustomUserDetails userDetails, // 삭제 권한을 확인할 사용자다.
        @Valid @RequestBody PostDeleteRequestDto request // 현재 version을 body로 받아 낙관적 충돌을 검사한다.
){
    return postService.deletePost(postId, userDetails.getUserId(), request); // Service가 soft delete와 counter 검증을 수행한다.
}

@PostMapping("/{postId}/likes") // 좋아요 생성 endpoint다.
public LikeResponseDto likePost( // 매개변수는 위의 실제 선언과 동일하다.
        @PathVariable("postId") Long postId,
        @AuthenticationPrincipal CustomUserDetails userDetails
){
    return postService.likePost(postId, userDetails.getUserId()); // Service가 Like row와 counter를 갱신한다.
}
```

`@AuthenticationPrincipal`은 사용자가 직접 만든 타입 주입 문법이 아니라 Spring Security가 현재 인증 객체의 principal을 메서드 인자로 넣어 주는 annotation입니다. `userDetails.getUserId()`로 얻은 값은 JWT Filter가 검증한 access token의 사용자 ID에서 시작합니다. 프론트의 `postId`와 서버의 `@PathVariable`이 연결되고, 로그인 사용자는 header의 token에서 연결됩니다.

### 상세 Service가 만드는 값

실제 파일: `/Users/miles/Documents/GitHub/kakao_tech_bootcamp_study/study12/backend/src/main/java/kr/adapterz/springdatajpa/service/PostService.java`

```java
@Transactional
public PostViewResponseDto getPostView(Long postId, Long loginUserId) {
    Post post = getViewablePost(postId);
    User loginUser = getLoginUser(loginUserId);

    List<Comment> comments = commentRepository.findByPostWithUser(post);
    List<CommentResponseDto> commentResponseDtos = new ArrayList<>();

    for (Comment comment : comments) {
        boolean isMyComment=comment.getUser().getUserId().equals(loginUserId);
        CommentResponseDto commentResponseDto =
                new CommentResponseDto(comment, comment.getUser(),isMyComment);
        commentResponseDtos.add(commentResponseDto);
    }

    boolean isLiked = likeRepository.existsByPostAndUser(post, loginUser);
    boolean isReported = postReportRepository.existsByPostAndUser(post, loginUser);
    boolean isMine = post.getUser().getUserId().equals(loginUserId);

    long baselineViewCount = post.getPostViewCount().getViewCount();
    long updatedViewCount = viewCountUpdater.increment(
            postId,
            baselineViewCount
    );

    return new PostViewResponseDto(
            post,
            post.getPostCounter(),
            updatedViewCount,
            commentResponseDtos,
            isLiked,
            isReported,
            isMine
    );
}
```

```java
Post post = getViewablePost(postId); // 삭제되지 않았고 신고 기준을 통과한 게시글 Entity를 조회한다.
User loginUser = getLoginUser(loginUserId); // 인증된 사용자가 아직 활성 계정인지 확인한다.

List<Comment> comments = commentRepository.findByPostWithUser(post); // 게시글의 댓글과 작성자 정보를 조회한다.
List<CommentResponseDto> commentResponseDtos = new ArrayList<>(); // Entity를 JSON용 DTO로 바꿔 담을 빈 목록을 만든다.

boolean isLiked = likeRepository.existsByPostAndUser(post, loginUser); // 현재 사용자가 이 글을 좋아요 했는지 확인한다.
boolean isReported = postReportRepository.existsByPostAndUser(post, loginUser); // 현재 사용자가 신고했는지 확인한다.
boolean isMine = post.getUser().getUserId().equals(loginUserId); // 글 작성자 ID와 로그인 ID를 비교한다.

long baselineViewCount = post.getPostViewCount().getViewCount(); // DB에 저장된 조회수 기준값을 읽는다.
long updatedViewCount = viewCountUpdater.increment(postId, baselineViewCount); // 조회수 저장소를 증가시키고 화면에 보여줄 값을 받는다.

return new PostViewResponseDto( // 게시글·counter·조회수·댓글·사용자별 상태를 response DTO 하나로 묶는다.
        post, // 제목·내용·작성 시각 등의 Entity 값이다.
        post.getPostCounter(), // 좋아요·신고 counter 원본이다.
        updatedViewCount, // Redis 또는 DB fallback을 거친 조회수다.
        commentResponseDtos, // 댓글 Entity를 변환한 목록이다.
        isLiked, // 좋아요 버튼의 현재 상태를 결정한다.
        isReported, // 신고 버튼을 이미 눌렀는지 결정한다.
        isMine // 수정·삭제 버튼을 표시할지 결정한다.
);
```

여기서 `isMine`, `isLiked`, `isReported`는 DB Entity의 고정 field가 아니라 **현재 로그인 사용자에 따라 달라지는 계산 결과**입니다. 그래서 같은 게시글을 두 사용자가 조회하면 본문은 같아도 버튼 상태가 달라질 수 있습니다. `updatedViewCount`는 조회수 장에서 다룬 `ViewCountUpdater`의 반환값이며, 상세 DTO 생성 전에 계산됩니다.

## 15.3 상세 흐름을 읽을 때 미리 확인할 공통 규칙

- `postApi.js`의 `getPost`, `likePost`, `unlikePost`, `reportPost`, `deletePost`, `createComment`, `updateComment`, `deleteComment`는 14번에서 전체 원문을 확인했습니다. 이 문서에서는 각 호출의 매개변수와 응답 사용처를 추적합니다.
- `api.js`는 fetch·Authorization·401 refresh를 담당합니다. 이 문서의 component가 직접 `fetch`하지 않는 이유는 13번에서 확인한 공통 입구를 재사용하기 때문입니다.
- `ConfirmModal`, `ErrorView`, `PageLayout`의 JSX 구조는 13번에서 확인했습니다. 여기서는 상세·회원정보 page가 어떤 callback과 state를 넣는지만 설명합니다.


## 15.4 `PostDetailPage.jsx`: 상세 화면의 상태 소유자

실제 파일: `/Users/miles/Documents/GitHub/KTB4_Miles_Week12_Front/src/pages/posts/PostDetailPage.jsx`

### 이 파일을 지금 읽는 이유

상세 화면의 하위 컴포넌트는 직접 API를 호출하지 않고 대부분 callback을 props로 받습니다. 먼저 page를 읽어야 `post`, `comments`, modal, 좋아요 동시 요청 방지 값이 어디서 만들어지고 각 자식으로 어떻게 전달되는지 이해할 수 있습니다.

### 책임·호출 관계·값의 이동

- 호출자: `AppRoutes.jsx`가 `/posts/:postId` route에서 렌더링합니다.
- 호출하는 파일: `postApi.js`, `ConfirmModal.jsx`, `ErrorView.jsx`, `PostDetailCard.jsx`, `CommentSection.jsx`.
- 외부 입력: URL의 `postId`, JWT가 붙은 GET/POST/PATCH/DELETE 응답.
- 내부 상태: `post`, `comments`, `loadError`, `retryVersion`, `isLikeSubmitting`, `modal`.
- 반환값 사용 위치: `postApi.getPost` 결과는 `setPost`와 `setComments`; like/report/delete/comment API 결과는 local state 또는 navigation에 사용됩니다.
- 예외 지점: 상세 GET, 좋아요, modal action 안의 신고·삭제·댓글 삭제. GET 오류는 `ErrorView`, action 오류는 `window.alert`로 처리됩니다.

### 전체 실제 코드

```jsx
import { useEffect, useRef, useState } from "react";
import { useNavigate, useParams } from "react-router-dom";

import { postApi } from "../../api/postApi.js";
import ConfirmModal from "../../components/common/ConfirmModal.jsx";
import ErrorView from "../../components/common/ErrorView.jsx";
import { ErrorBoundary } from "react-error-boundary";
import PageLayout from "../../components/layout/PageLayout.jsx";
import CommentSection from "../../components/posts/CommentSection.jsx";
import PostDetailCard from "../../components/posts/PostDetailCard.jsx";
import { getErrorMessage } from "../../utils/errorMessage.js";
import "../../styles/posts.css";

const REPORT_BLOCK_THRESHOLD = 5;

function PostDetailPage() {
    const { postId } = useParams();
    const navigate = useNavigate();
    const [post, setPost] = useState(null);
    const [comments, setComments] = useState([]);
    const [loadError, setLoadError] = useState(null);
    const [retryVersion, setRetryVersion] = useState(0);
    const [isLikeSubmitting, setIsLikeSubmitting] = useState(false);
    const [modal, setModal] = useState(null);
    const likeRequestRef = useRef(false);

    useEffect(() => {
        const controller = new AbortController();
        setPost(null);
        setComments([]);
        setLoadError(null);

        postApi.getPost(postId, { signal: controller.signal })
            .then((result) => {
                setPost(result);
                setComments(result.comments);
                setLoadError(null);
            })
            .catch((requestError) => {
                if (controller.signal.aborted || requestError?.name === "AbortError") {
                    return;
                }
                setLoadError(requestError);
            });

        return () => {
            controller.abort();
        };
    }, [postId, retryVersion]);

    function retryLoadPost() {
        setLoadError(null);
        setRetryVersion((previous) => previous + 1);
    }

    function openModal(title, description, onConfirm) {
        setModal({ title, description, onConfirm });
    }

    async function confirmModal() {
        const action = modal?.onConfirm;
        setModal(null);
        if (!action) {
            return;
        }

        try {
            await action();
        } catch (actionError) {
            window.alert(getErrorMessage(actionError));
        }
    }

    async function handleLike() {
        if (likeRequestRef.current) {
            return;
        }

        try {
            likeRequestRef.current = true;
            setIsLikeSubmitting(true);
            const result = post.isLiked
                ? await postApi.unlikePost(post.postId)
                : await postApi.likePost(post.postId);
            setPost((previous) => ({
                ...previous,
                isLiked: !previous.isLiked,
                likeCount: result?.likeCount ?? previous.likeCount + (previous.isLiked ? -1 : 1),
            }));
        } catch (likeError) {
            window.alert(getErrorMessage(likeError, "좋아요 처리에 실패했습니다."));
        } finally {
            likeRequestRef.current = false;
            setIsLikeSubmitting(false);
        }
    }

    function requestReport() {
        openModal(
            "글을 신고하겠습니까?",
            "신고 후에는 취소할 수 없습니다.",
            async () => {
                const result = await postApi.reportPost(post.postId);
                const nextReportCount =
                    result?.reportCount ?? post.reportCount + 1;

                if (nextReportCount >= REPORT_BLOCK_THRESHOLD) {
                    navigate("/posts", { replace: true });
                    return;
                }

                setPost((previous) => ({
                    ...previous,
                    isReported: true,
                    reportCount: nextReportCount,
                }));
            },
        );
    }

    function requestPostDelete() {
        openModal(
            "글을 삭제하겠습니까?",
            "삭제한 내용은 복구할 수 없습니다.",
            async () => {
                await postApi.deletePost(post.postId, post.version);
                navigate("/posts", { replace: true });
            },
        );
    }

    function requestCommentDelete(commentId) {
        openModal(
            "댓글을 삭제하겠습니까?",
            "삭제한 내용은 복구할 수 없습니다.",
            async () => {
                await postApi.deleteComment(post.postId, commentId);
                setComments((previous) => (
                    previous.filter((comment) => comment.commentId !== commentId)
                ));
            },
        );
    }

    function handleCommentCreated(comment) {
        setComments((previous) => [...previous, comment]);
    }

    function handleCommentUpdated(comment) {
        setComments((previous) => previous.map((item) => (
            item.commentId === comment.commentId ? comment : item
        )));
    }

    return (
        <PageLayout
            pageClassName="post-detail-page"
            mainClassName="post-detail-main"
            title="글 상세"
            showBack
            backTo="/posts"
        >
            {loadError ? (
                <ErrorView
                    title="게시글을 불러오지 못했습니다."
                    message={getErrorMessage(loadError, "잠시 후 다시 시도해주세요.")}
                    onRetry={retryLoadPost}
                />
            ) : post ? (
                <>
                    <ErrorBoundary fallback={<ErrorView title="게시글을 표시하지 못했습니다." />}>
                        <PostDetailCard
                            post={post}
                            commentCount={comments.length}
                            isLikeSubmitting={isLikeSubmitting}
                            onDelete={requestPostDelete}
                            onReport={requestReport}
                            onLike={handleLike}
                        />
                    </ErrorBoundary>
                    <ErrorBoundary fallback={<ErrorView title="댓글 영역을 표시하지 못했습니다." />}>
                        <CommentSection
                            postId={post.postId}
                            comments={comments}
                            onCommentCreated={handleCommentCreated}
                            onCommentUpdated={handleCommentUpdated}
                            onRequestDelete={requestCommentDelete}
                        />
                    </ErrorBoundary>
                </>
            ) : null}

            <ConfirmModal
                isOpen={Boolean(modal)}
                title={modal?.title}
                description={modal?.description}
                onCancel={() => setModal(null)}
                onConfirm={confirmModal}
            />
        </PageLayout>
    );
}

export default PostDetailPage;
```

### 코드 일부와 바로 아래 설명: route parameter와 상세 조회

```jsx
const { postId } = useParams(); // React Router가 URL /posts/:postId에서 추출한 문자열을 받는다.
const [post, setPost] = useState(null); // 아직 응답 전에는 null, 성공 후에는 상세 response object다.
const [comments, setComments] = useState([]); // post.comments를 별도 배열로 관리해 댓글 추가·수정을 즉시 반영한다.

useEffect(() => {

    setPost(null); // postId가 바뀌면 이전 글이 잠깐 보이지 않도록 초기화한다.
    setComments([]); // 이전 글의 댓글도 함께 비운다.
    setLoadError(null); // 새 요청을 시작하므로 이전 오류를 제거한다.

    postApi.getPost(postId, { signal: controller.signal }) // 14번에서 본 API module을 호출하고 signal을 전달한다.
        .then((result) => { // Promise가 정상 완료될 때 응답 정규화 결과를 받는다.
            setPost(result); // 상세 카드가 읽을 게시글 상태를 저장한다.
            setComments(result.comments); // 부모가 댓글 배열의 소유자가 된다.
        })
        .catch((requestError) => { // 네트워크·HTTP 오류가 reject되면 실행된다.
            if (controller.signal.aborted || requestError?.name === "AbortError") {
                return; // 화면이 사라진 뒤의 정상 취소는 오류 화면으로 만들지 않는다.
            }
            setLoadError(requestError); // 실제 실패만 ErrorView 조건으로 전달한다.
        });

    return () => {
        controller.abort(); // postId가 바뀌거나 unmount될 때 이전 요청을 취소한다.
    };
}, [postId, retryVersion]); // URL 글 ID 또는 retryVersion이 바뀔 때 effect를 다시 실행한다.
```

`useParams()`의 반환값은 URL segment이므로 이 코드의 `postId`는 처음부터 숫자 `Long`이 아닙니다. `postApi`가 URL 문자열에 넣고, backend의 `@PathVariable Long`이 서버에서 숫자로 변환합니다. `useEffect`의 cleanup은 응답을 무조건 삭제하는 기능이 아니라, 화면이 더 이상 그 요청의 결과를 사용할 수 없을 때 브라우저 fetch를 취소하는 기능입니다.

### 코드 일부와 바로 아래 설명: 좋아요 동시 요청 방지

```jsx
const likeRequestRef = useRef(false); // 렌더링과 무관하게 현재 좋아요 요청 중인지 보관한다.

async function handleLike() {
    if (likeRequestRef.current) {
        return; // 같은 요청이 끝나기 전 두 번째 클릭은 API 호출하지 않는다.
    }

    try {
        likeRequestRef.current = true; // await 전에 잠금 값을 먼저 세운다.
        setIsLikeSubmitting(true); // 버튼 disabled와 aria-busy를 갱신한다.
        const result = post.isLiked
            ? await postApi.unlikePost(post.postId) // 현재 true면 취소 endpoint다.
            : await postApi.likePost(post.postId); // 현재 false면 생성 endpoint다.
        setPost((previous) => ({
            ...previous, // title·content 등 바꾸지 않은 field는 유지한다.
            isLiked: !previous.isLiked, // 성공했으므로 현재 상태를 반전한다.
            likeCount: result?.likeCount ?? previous.likeCount + (previous.isLiked ? -1 : 1), // 서버 count를 우선 사용하고 없으면 이전 상태에서 계산한다.
        }));
    } finally {
        likeRequestRef.current = false; // 성공·실패 모두 다음 요청을 허용한다.
        setIsLikeSubmitting(false); // 버튼을 다시 활성화한다.
    }
}
```

`useRef`의 `.current` 변경은 재렌더링을 일으키지 않지만, 같은 component instance가 유지되는 동안 값을 보존합니다. 이 값은 UI 표시용 state와 달리 중복 실행을 막는 내부 잠금입니다. `isLikeSubmitting`도 함께 사용하는 이유는 ref만 쓰면 화면의 disabled 상태가 바뀌지 않기 때문입니다.

```jsx

async function confirmModal() {
    const action = modal?.onConfirm; // 현재 modal이 없을 수도 있으므로 optional chaining으로 읽는다.
    setModal(null); // 확인 직후 modal을 먼저 닫아 중복 확인 클릭을 줄인다.
    if (!action) {
        return; // 저장된 action이 없으면 아무 작업도 하지 않는다.
    }

    try {
        await action(); // 신고·글 삭제·댓글 삭제 중 선택된 callback을 여기서 실제 실행한다.
    } catch (actionError) {
        window.alert(getErrorMessage(actionError)); // callback 내부 API 오류를 공통 문구로 바꿔 알린다.
    }
}
```

`openModal` 호출 자체는 신고나 삭제 요청을 보내지 않습니다. 먼저 modal state에 함수를 저장하고, 사용자가 ConfirmModal의 확인 버튼을 누르면 `onConfirm={confirmModal}`을 통해 그 함수를 실행합니다. 즉 버튼을 눌렀을 때의 실행과 modal을 화면에 표시하는 상태 변경이 분리되어 있습니다.

### 코드 일부와 바로 아래 설명: 댓글 배열의 불변 갱신

```jsx
function requestCommentDelete(commentId) {
    openModal("댓글을 삭제하겠습니까?", "삭제한 내용은 복구할 수 없습니다.", async () => {
        await postApi.deleteComment(post.postId, commentId); // 서버 삭제가 성공해야 화면에서도 제거한다.
        setComments((previous) => (
            previous.filter((comment) => comment.commentId !== commentId) // 삭제 대상만 제외한 새 배열을 만든다.
        ));
    });
}

function handleCommentCreated(comment) {
    setComments((previous) => [...previous, comment]); // 기존 배열을 복사하고 새 댓글을 뒤에 추가한다.
}

function handleCommentUpdated(comment) {
    setComments((previous) => previous.map((item) => (
        item.commentId === comment.commentId ? comment : item // 같은 ID만 새 객체로 교체한다.
    )));
}
```

`filter`, `map`, spread(`...`)는 기존 배열을 직접 변경하지 않고 새 배열을 반환합니다. React state는 새 참조를 기준으로 변경을 감지하므로, `previous.push()`처럼 기존 배열을 직접 바꾸지 않고 새 배열을 저장합니다. 삭제 응답은 body를 화면에 쓸 필요가 없으므로 성공 여부만 확인한 뒤 local 배열을 갱신합니다.

## 15.9 `CommentEditor.jsx`: 등록과 수정의 공통 form

실제 파일: `/Users/miles/Documents/GitHub/KTB4_Miles_Week12_Front/src/components/posts/CommentEditor.jsx`

```jsx
import { useEffect, useState } from "react";

import { postApi } from "../../api/postApi.js";
import { getErrorMessage } from "../../utils/errorMessage.js";

function CommentEditor({
    postId,
    editingComment,
    onCreated,
    onUpdated,
    onCancelEdit,
}) {
    const [content, setContent] = useState("");
    const [isSubmitting, setIsSubmitting] = useState(false);
    const [error, setError] = useState("");

    useEffect(() => {
        setContent(editingComment?.content ?? "");
    }, [editingComment]);

    async function handleSubmit(event) {
        event.preventDefault();
        const trimmedContent = content.trim();
        if (!trimmedContent || isSubmitting) {
            return;
        }

        try {
            setIsSubmitting(true);
            setError("");
            if (editingComment) {
                const comment = await postApi.updateComment(
                    postId,
                    editingComment.commentId,
                    trimmedContent,
                );
                onUpdated(comment);
            } else {
                const comment = await postApi.createComment(postId, trimmedContent);
                onCreated(comment);
            }
            setContent("");
            onCancelEdit();
        } catch (submitError) {
            setError(getErrorMessage(submitError, "댓글 처리에 실패했습니다."));
        } finally {
            setIsSubmitting(false);
        }
    }

    return (
        <form className="comment-form" noValidate onSubmit={handleSubmit}>
            <textarea
                className="comment-input"
                value={content}
                placeholder="댓글을 남겨주세요!"
                onChange={(event) => setContent(event.target.value)}
            />
            <div className="comment-form-divider" />
            <p className="comment-form-error" aria-live="polite">
                {error}
            </p>
            <button
                type="submit"
                className="comment-submit-button"
                disabled={!content.trim() || isSubmitting}
            >
                {editingComment ? "댓글 수정" : "댓글 등록"}
            </button>
        </form>
    );
}

export default CommentEditor;
```

7. 댓글 삭제는 API 성공 후 `filter`로 local 목록에서 제거합니다.
8. 권한·신고 기준은 화면 조건과 backend 검사를 모두 통과해야 합니다. 화면의 `disabled`나 `canModify`만으로 보안을 보장하지 않습니다.

## 15.13 `PostEditPage.jsx`: 원본 조회와 version 전달

실제 파일: `/Users/miles/Documents/GitHub/KTB4_Miles_Week12_Front/src/pages/posts/PostEditPage.jsx`

### 책임·호출 관계

- 호출자: `PostDetailCard`의 `Link to="/posts/{postId}/edit"` 또는 route 직접 접근.
- 호출하는 파일: `useParams`, `postApi.getPost`, `postApi.updatePost`, `PostEditor`, `ErrorView`, `PageLayout`.
- 외부 입력: URL `postId`, GET 상세 response, Editor payload.
- 내부 값: `originalPost`, `loadError`, `retryVersion`.
- 예외: 조회 AbortError는 무시하고, 그 외 조회 오류는 ErrorView; 수정 오류는 PostEditor의 catch로 전달됩니다.
- 서버가 받는 version: `originalPost.version`을 payload에 병합합니다.

### 전체 실제 코드

```jsx
import { useEffect, useState } from "react";
import { useNavigate, useParams } from "react-router-dom";

import { postApi } from "../../api/postApi.js";
import ErrorView from "../../components/common/ErrorView.jsx";
import { ErrorBoundary } from "react-error-boundary";
import PageLayout from "../../components/layout/PageLayout.jsx";
import PostEditor from "../../components/posts/PostEditor.jsx";
import { getErrorMessage } from "../../utils/errorMessage.js";
import "../../styles/posts.css";

const REPORT_BLOCK_THRESHOLD = 5;

function PostEditPage() {
    const { postId } = useParams();
    const navigate = useNavigate();
    const [originalPost, setOriginalPost] = useState(null);
    const [loadError, setLoadError] = useState(null);
    const [retryVersion, setRetryVersion] = useState(0);

    useEffect(() => {
        const controller = new AbortController();
        setOriginalPost(null);
        setLoadError(null);

        postApi.getPost(postId, { signal: controller.signal })
            .then((post) => {
                if (!post.isMine || post.reportCount >= REPORT_BLOCK_THRESHOLD) {
                    navigate(`/posts/${postId}`, { replace: true });
                    return;
                }
                setOriginalPost(post);
                setLoadError(null);
            })
            .catch((requestError) => {
                if (controller.signal.aborted || requestError?.name === "AbortError") {
                    return;
                }
                setLoadError(requestError);
            });

        return () => {
            controller.abort();
        };
    }, [navigate, postId, retryVersion]);

    function retryLoadPost() {
        setLoadError(null);
        setRetryVersion((previous) => previous + 1);
    }

    return (
        <PageLayout
            pageClassName="post-edit-page"
            mainClassName="post-edit-main"
            title="글 수정"
            showBack
            backTo={`/posts/${postId}`}
        >
            <h2 className="post-edit-title">대나무숲 글 수정</h2>
            {loadError ? (
                <ErrorView
                    title="수정할 게시글을 불러오지 못했습니다."
                    message={getErrorMessage(loadError, "잠시 후 다시 시도해주세요.")}
                    onRetry={retryLoadPost}
                />
            ) : originalPost ? (
                <ErrorBoundary fallback={<ErrorView title="게시글 수정 양식을 표시하지 못했습니다." />}>
                    <PostEditor
                        mode="edit"
                        initialValues={originalPost}
                        onSubmit={async (payload) => {
                            await postApi.updatePost(postId, {
                                ...payload,
                                version: originalPost.version,
                            });
                            navigate(`/posts/${postId}`, { replace: true });
                        }}
```

### 코드 일부와 바로 아래 설명: 조회 effect와 접근 조건

```jsx
const { postId } = useParams(); // route parameter를 문자열로 받는다.
const [originalPost, setOriginalPost] = useState(null); // 조회 성공 전 null, 성공 후 편집 원본 object다.

useEffect(() => {
    const controller = new AbortController(); // 이 조회의 취소 도구를 만든다.
    setOriginalPost(null); // 재시도나 postId 변경 시 이전 원본을 제거한다.

    postApi.getPost(postId, { signal: controller.signal }) // 상세 endpoint를 재사용한다.
        .then((post) => {

                navigate(`/posts/${postId}`, { replace: true }); // 본인 글이 아니거나 신고 차단 기준이면 상세로 되돌린다.
                return; // 권한 없는 사용자는 Editor를 만들지 않는다.
            }
            setOriginalPost(post); // 허용된 경우에만 원본을 Editor로 넘긴다.
        })
        .catch((requestError) => {
            if (controller.signal.aborted || requestError?.name === "AbortError") {
                return; // 취소는 오류 화면이 아니다.
            }
            setLoadError(requestError); // 실제 실패는 재시도 가능한 화면으로 전환한다.
        });

    return () => {
        controller.abort(); // cleanup에서 이전 GET을 취소한다.
    };
}, [navigate, postId, retryVersion]); // navigate·postId·retryVersion이 바뀌면 새 effect다.
```

`navigate`를 dependency 배열에 넣은 이유는 effect가 사용하는 외부 함수 참조를 명시하기 위해서입니다. `retryVersion`은 재시도 버튼이 같은 `postId`로도 effect를 다시 실행하게 하는 숫자 key입니다. 이 page의 접근 조건은 UI 조건이며, PATCH 시 backend도 `validatePostModificationPermission`과 version 검사를 다시 수행합니다.

여기서 `version`은 작성자가 수정 화면을 연 뒤 다른 요청이 먼저 글을 변경했는지 판단하는 기준입니다. 프론트가 보내는 값은 “현재 최신 version이라고 보장”하는 값이 아니라 “내가 조회했을 때 알고 있던 version”입니다. backend가 다르면 conflict 예외를 반환하고, `PostEditor`의 공통 submit 오류 문구로 표시됩니다.

현재 백엔드에서는 `isFixed`라는 별도 수정 여부 field를 사용하지 않습니다. 수정 요청이 들어오면 `PostService.fixPost()`가 서버의 현재 제목·내용·이미지 목록과 요청값을 직접 비교합니다. 세 값이 모두 같으면 `PostFixResponseDto`만 반환하고 `post.update()`와 version 증가를 실행하지 않습니다. 제목·내용은 같지만 이미지 목록이 다르면 `OPTIMISTIC_FORCE_INCREMENT`를 요청한 뒤 이미지를 변경하므로, 이미지 변경도 version 충돌 기준에 포함됩니다. 제목이나 내용이 다르면 일반적인 `post.update()`와 `@Version` 검사가 적용됩니다. 프론트는 이 분기를 계산하지 않고, 조회 당시 `version`과 입력값만 보내며 최종 판단은 서버가 담당합니다.

따라서 예전 화면 응답이나 문서에서 `post.isFixed`를 찾으면 현재 계약에 없는 과거 field로 구분해야 합니다. 현재 `PostViewResponseDto`에도 `isFixed`가 없고, 수정 여부를 화면에 표시하는 값도 이 page에는 없습니다.

이미지도 대표 이미지 하나를 별도 field로 주고받지 않습니다. backend 응답의
`imageUrls`는 `PostImage` 목록 전체를 순서대로 담고, `PostImageGallery`가 배열의 각
항목을 `img` element로 렌더링합니다. 수정 요청의 `imageFiles`도 단일 문자열이 아니라
목록이며, 새 파일이 없으면 기존 `imageUrls` 목록을 그대로 전송합니다.

### 전체 실제 코드

```jsx
import { useEffect, useState } from "react";

import TextArea from "../common/TextArea.jsx";
import { getErrorMessage } from "../../utils/errorMessage.js";
import {
    fileToDataUrl,
    getPostImageFilesError,
} from "../../utils/file.js";
import PostImagePicker from "./PostImagePicker.jsx";

function PostEditor({ mode, initialValues, onSubmit }) {
    const [form, setForm] = useState({ title: "", content: "" });
    const [files, setFiles] = useState([]);
    const [error, setError] = useState("");
    const [isSubmitting, setIsSubmitting] = useState(false);

    useEffect(() => {
        setForm({
            title: initialValues?.title ?? "",
            content: initialValues?.content ?? "",
        });
    }, [initialValues]);

    function handleFilesChange(event) {
        const nextFiles = Array.from(event.target.files ?? []);
        const imageError = getPostImageFilesError(nextFiles);

        if (imageError) {
            event.target.value = "";
            setFiles([]);
            setError(`*${imageError}`);
            return;
        }

        setFiles(nextFiles);
        setError("");
    }

    async function handleSubmit(event) {
        event.preventDefault();
        const title = form.title.trim();
        const content = form.content.trim();
        const imageError = getPostImageFilesError(files);

        if (!title || !content) {
            setError("*글 제목과 이야기 내용을 모두 작성해주세요.");
            return;

            setError(`*${imageError}`);
            return;

        try {
            setIsSubmitting(true);
            setError("");
            const imageFiles = files.length

                : initialValues?.imageUrls ?? [];

                title,
                content,
                imageFiles,
            });
        } catch (submitError) {
            setError(`*${getErrorMessage(submitError, "요청 처리에 실패했습니다.")}`);
        } finally {
            setIsSubmitting(false);
        }

    const classPrefix = isEdit ? "post-edit" : "post-create";

    return (

                maxLength="26"

            />
            <label htmlFor="postContentInput" className={`${classPrefix}-label ${classPrefix}-label--content`}>
                이야기 내용*
            </label>
            <TextArea
                id="postContentInput"
                className={isEdit ? "post-content-input" : "post-create-content-input"}
                value={form.content}
                placeholder="오늘 대나무숲에 남기고 싶은 이야기를 입력해주세요."
                onChange={(event) => setForm((previous) => ({ ...previous, content: event.target.value }))}
            />
            <p className={`${classPrefix}-helper`}>{error}</p>
            <label className={`${classPrefix}-label ${classPrefix}-label--image`}>
                첨부 이미지
            </label>
            <PostImagePicker

                existingImageCount={initialValues?.imageUrls?.length ?? 0}
```


### 코드 일부와 바로 아래 설명: 파일 검증과 기존 이미지 보존

```jsx
function handleFilesChange(event) {
    const nextFiles = Array.from(event.target.files ?? []); // FileList를 일반 배열로 바꾼다.

        return; // 유효하지 않은 파일은 다음 단계로 가지 않는다.
    }

    setFiles(nextFiles); // 검증된 File 배열을 저장한다.
    setError(""); // 이전 오류를 지운다.

const imageFiles = files.length
    ? await Promise.all(files.map(fileToDataUrl)) // 새 파일을 하나라도 골랐으면 모두 Data URL로 변환한다.
```

여기서 `files`는 브라우저 `File` 객체 배열이고, `imageFiles`는 backend DTO가 받을 Data URL 문자열 배열입니다. `Promise.all`은 여러 변환 Promise가 모두 성공할 때까지 기다리며, 하나라도 실패하면 전체가 reject되어 `catch`로 이동합니다. 새 파일이 없는 수정 요청에서 기존 이미지가 빈 배열로 덮어써지지 않도록 `initialValues.imageUrls`를 fallback으로 사용합니다.

## 15.16 작성·수정 전체 흐름

### 작성

1. 사용자가 `/posts/new`에 들어오면 `PostCreatePage`가 `PostEditor(mode="create")`를 렌더링합니다.
2. title/content는 controlled state에 저장되고, 파일 선택은 `PostImagePicker` → `handleFilesChange`로 전달됩니다.
3. submit 시 trim, 빈 값, 이미지 검증을 순서대로 통과해야 합니다.
4. 선택한 File은 `Promise.all(files.map(fileToDataUrl))`로 Data URL 문자열이 됩니다.
5. `postApi.createPost`가 body를 JSON으로 보내고 `api.js`가 공통 인증·오류 처리를 합니다.
6. 성공하면 `navigate("/posts", { replace: true })`; 실패하면 Editor form 아래 오류가 유지됩니다.

### 수정

1. 상세 카드의 수정 Link가 `/posts/{postId}/edit`로 이동합니다.
2. `PostEditPage`가 같은 상세 API를 호출해 원본을 가져옵니다.
3. `isMine`이 false이거나 신고 수가 5 이상이면 Editor를 만들지 않고 상세로 돌아갑니다.
4. 허용되면 `originalPost`가 `PostEditor.initialValues`로 전달되어 기존 제목·내용이 preload됩니다.
5. 새 이미지가 없으면 기존 `imageUrls`, 새 이미지가 있으면 변환된 Data URL 배열을 전송합니다.
6. 조회 당시 `version`을 payload에 추가해 backend가 수정 충돌을 판단합니다.
7. 동일한 제목·내용·이미지를 다시 보내면 backend가 변경 없음으로 처리하므로, 프론트는 `isFixed`를 별도로 보내지 않습니다.
8. 성공하면 상세로 이동하고, 실패하면 Editor가 오류 문구를 표시합니다.
9. 제목·내용이 같아도 이미지가 바뀌면 backend가 version을 강제로 증가시키고 새 이미지 목록을 저장합니다.

```jsx
import { useEffect, useRef, useState } from "react";
import { useNavigate } from "react-router-dom";

import { userApi } from "../../api/userApi.js";
import { authStorage } from "../../auth/authStorage.js";
import ConfirmModal from "../../components/common/ConfirmModal.jsx";
import ErrorView from "../../components/common/ErrorView.jsx";
import Toast from "../../components/common/Toast.jsx";
import { ErrorBoundary } from "react-error-boundary";
import InfoBanner from "../../components/layout/InfoBanner.jsx";
import PageLayout from "../../components/layout/PageLayout.jsx";
import ProfileEditForm from "../../components/user/ProfileEditForm.jsx";
import {
    getErrorMessage,
    hasErrorCode,
} from "../../utils/errorMessage.js";
import {
    fileToDataUrl,
    getImageFileError,
} from "../../utils/file.js";
import { isValidNickname } from "../../utils/validation.js";
import "../../styles/user.css";

function ProfileEditPage() {
    const navigate = useNavigate();
    const toastTimerRef = useRef(null);
    const [user, setUser] = useState(null);
    const [nickname, setNickname] = useState("");
    const [newProfileImage, setNewProfileImage] = useState(null);
    const [previewUrl, setPreviewUrl] = useState(null);
    const [nicknameError, setNicknameError] = useState("");
    const [loadError, setLoadError] = useState(null);
    const [retryVersion, setRetryVersion] = useState(0);
    const [isSubmitting, setIsSubmitting] = useState(false);
    const [isWithdrawModalOpen, setIsWithdrawModalOpen] = useState(false);
    const [toast, setToast] = useState({ isVisible: false, message: "" });

    useEffect(() => {
        const controller = new AbortController();
        setLoadError(null);

        userApi.getMyInfo({ signal: controller.signal })
            .then((result) => {
                setUser(result);
                setNickname(result.nickname ?? "");
                setPreviewUrl(result.profileImage ?? null);
                setLoadError(null);
            })
            .catch((error) => {
                if (controller.signal.aborted || error?.name === "AbortError") {
                    return;
                }
                setLoadError(error);
            });

        return () => {
            controller.abort();
            window.clearTimeout(toastTimerRef.current);
        };
    }, [retryVersion]);

    function retryLoadProfile() {
        setLoadError(null);
        setRetryVersion((previous) => previous + 1);
    }

    function showToast(message) {
        window.clearTimeout(toastTimerRef.current);
        setToast({ isVisible: true, message });
        toastTimerRef.current = window.setTimeout(() => {
            setToast({ isVisible: false, message: "" });
        }, 2000);
    }

    function handleNicknameChange(event) {
        setNickname(event.target.value);
        setNicknameError("");
    }

    async function handleImageChange(event) {
        const file = event.target.files?.[0];
        if (!file) {
            return;
        }

        const imageError = getImageFileError(file);
        if (imageError) {
            event.target.value = "";
            window.alert(imageError);
            return;
        }

        try {
            const convertedImage = await fileToDataUrl(file);
            setNewProfileImage(convertedImage);
            setPreviewUrl(convertedImage);
        } catch {
            window.alert("프로필 이미지를 읽지 못했습니다.");
        }
    }

    async function handleSubmit(event) {
        event.preventDefault();
        if (!isValidNickname(nickname)) {
            setNicknameError("닉네임은 공백 없이 1~10자로 입력해주세요.");
            return;
        }

        try {
            setIsSubmitting(true);
            setNicknameError("");
            await userApi.updateProfile({
                nickname,
                profileImage: newProfileImage ?? user?.profileImage ?? null,
            });
            setUser((previous) => ({
                ...previous,
                nickname,
                profileImage: newProfileImage ?? previous.profileImage,
            }));
            setNewProfileImage(null);
            showToast("회원정보가 수정되었습니다.");
        } catch (error) {
            if (hasErrorCode(error, "EXISTED_NICKNAME")) {
                setNicknameError(getErrorMessage(error));
            } else {
                setNicknameError(getErrorMessage(error, "회원정보 수정에 실패했습니다."));
            }
        } finally {
            setIsSubmitting(false);
        }
    }

    async function handleWithdraw() {
        try {
            await userApi.deleteUser();
            authStorage.removeAccessToken();
            navigate("/login", { replace: true });
        } catch (error) {
            setIsWithdrawModalOpen(false);
            window.alert(getErrorMessage(error, "회원 탈퇴에 실패했습니다."));
        }
    }

    return (
        <PageLayout
            pageClassName="profile-edit-page"
            mainClassName="profile-edit-section"
            title="계정 설정"
            showBack
            backTo="/posts"
            profileImage={previewUrl}
        >
            <h2 className="profile-edit-title">회원정보 수정</h2>
            <InfoBanner
                eyebrow="Night Profile"
                title="숲에서 나를 나타내는 조각들"
                description="글과 댓글에 함께 붙는 닉네임과 사진을 정돈해요."
            />

            {loadError ? (
                <ErrorView
                    title="회원정보를 불러오지 못했습니다."
                    message={getErrorMessage(loadError, "잠시 후 다시 시도해주세요.")}
                    onRetry={retryLoadProfile}
                />
            ) : user ? (
                <ErrorBoundary fallback={<ErrorView title="회원정보 수정 양식을 표시하지 못했습니다." />}>
                    <ProfileEditForm
                        email={user.email}
                        nickname={nickname}
                        previewUrl={previewUrl}
                        nicknameError={nicknameError}
                        isSubmitting={isSubmitting}
                        onNicknameChange={handleNicknameChange}
                        onImageChange={handleImageChange}
                        onSubmit={handleSubmit}
                        onWithdraw={() => setIsWithdrawModalOpen(true)}
                    />
                </ErrorBoundary>
            ) : null}

            <ConfirmModal
                isOpen={isWithdrawModalOpen}
                title="회원 탈퇴하시겠습니까?"
                description="탈퇴한 계정은 복구할 수 없습니다. 작성한 글과 댓글은 남습니다."
                confirmText="탈퇴"
                onCancel={() => setIsWithdrawModalOpen(false)}
                onConfirm={handleWithdraw}
            />
            <Toast isVisible={toast.isVisible} message={toast.message} />
        </PageLayout>
    );
}

export default ProfileEditPage;
```

### 코드 일부와 바로 아래 설명: timeout ref와 toast

```jsx
function showToast(message) {
    window.clearTimeout(toastTimerRef.current); // 이전 toast의 종료 예약이 있으면 취소한다.
    setToast({ isVisible: true, message }); // 즉시 표시 상태와 문구를 저장한다.
    toastTimerRef.current = window.setTimeout(() => {
        setToast({ isVisible: false, message: "" }); // 2초 후 숨긴다.
    }, 2000);
}

return () => {
    controller.abort(); // page가 사라지면 진행 중인 사용자 조회를 취소한다.
    window.clearTimeout(toastTimerRef.current); // unmount 후 toast state를 바꾸는 timer를 제거한다.
};
```

`window.setTimeout`은 숫자 timeout ID를 반환하고 callback을 나중에 실행합니다. ID를 ref에 저장해 새 toast가 나오면 이전 timer를 취소할 수 있습니다. cleanup에서 timer를 제거하지 않으면 화면이 사라진 뒤에도 callback이 실행될 수 있습니다.

### 코드 일부와 바로 아래 설명: 이미지 선택과 닉네임 수정

```jsx
async function handleImageChange(event) {
    const file = event.target.files?.[0]; // multiple가 아니므로 첫 File만 사용한다.
    if (!file) {
        return; // 파일 선택창을 취소한 경우다.
    }

    const imageError = getImageFileError(file); // 13번에서 설명한 MIME·용량 검사를 호출한다.
    if (imageError) {
        event.target.value = ""; // 잘못된 파일을 다시 선택할 수 있도록 input을 비운다.
        window.alert(imageError); // 사용자에게 즉시 오류를 알린다.
        return;
    }

    const convertedImage = await fileToDataUrl(file); // FileReader 결과를 기다린다.
    setNewProfileImage(convertedImage); // 다음 PATCH payload에 사용할 값이다.
    setPreviewUrl(convertedImage); // 저장 전에도 화면 미리보기를 바꾼다.
}

function handleNicknameChange(event) {
    setNickname(event.target.value); // controlled input state를 갱신한다.
    setNicknameError(""); // 새 입력을 시작하면 이전 서버/검증 오류를 지운다.
}
```

파일 선택 검증 실패는 API를 보내기 전에 끝납니다. `fileToDataUrl` 실패는 `try/catch`의 alert로 이동합니다. 닉네임은 입력 중에는 문구를 지우고, submit 시 `isValidNickname`으로 다시 검사하므로 입력 event만으로 유효성을 확정하지 않습니다.

서버가 성공했다고 해서 GET을 다시 호출하지 않고 local `user`를 갱신합니다. 이 코드는 PATCH 응답 body를 사용하지 않고, 요청에 사용한 값으로 화면을 맞춥니다. 서버가 정규화된 닉네임이나 다른 이미지 URL을 반환하는 구조인지는 현재 이 page 코드만으로 확인할 수 없으며, 현재 구현은 재조회하지 않습니다.

### 코드 일부와 바로 아래 설명: 탈퇴

```jsx
async function handleWithdraw() {
    try {
        await userApi.deleteUser(); // DELETE /users 성공을 기다린다.
        authStorage.removeAccessToken(); // 브라우저의 access token을 제거한다.

}
```

탈퇴 확인 modal을 열기만 해서는 API가 실행되지 않습니다. `onWithdraw={() => setIsWithdrawModalOpen(true)}`가 modal을 열고, `ConfirmModal`의 `onConfirm={handleWithdraw}`가 사용자의 최종 확인 후 DELETE를 실행합니다. 서버의 탈퇴는 soft delete와 active session revoke를 수행하며, 프론트는 성공 후 local access token만 제거합니다.

```jsx
    hasErrorCode,
} from "../../utils/errorMessage.js";
import { isValidPassword } from "../../utils/validation.js";
import "../../styles/user.css";

const EMPTY_FORM = {
    currentPassword: "",
    password: "",
    passwordCheck: "",
};

const EMPTY_ERRORS = {
    currentPassword: "",
    password: "",
    passwordCheck: "",
};

function getFieldError(name, nextForm) {
    if (name === "currentPassword") {
        return nextForm.currentPassword ? "" : "현재 비밀번호를 입력해주세요.";
    }
    if (name === "password") {
        return isValidPassword(nextForm.password)
            ? ""
            : "8~20자의 영문 대·소문자, 숫자, 특수문자를 사용해주세요.";
    }
    if (name === "passwordCheck") {
        return nextForm.password === nextForm.passwordCheck
            ? ""
            : "새 비밀번호가 일치하지 않습니다.";
    }
    return "";
}

function PasswordEditPage() {
    const navigate = useNavigate();
    const [form, setForm] = useState(EMPTY_FORM);
    const [errors, setErrors] = useState(EMPTY_ERRORS);
    const [isSubmitting, setIsSubmitting] = useState(false);
    const isFormValid =
        Boolean(form.currentPassword) &&
        isValidPassword(form.password) &&
        form.password === form.passwordCheck;

    function handleChange(event) {
        const { name, value } = event.target;
        const nextForm = { ...form, [name]: value };

        setForm(nextForm);
        setErrors((previous) => {
            const nextErrors = {
                ...previous,
                [name]: getFieldError(name, nextForm),
            };

            if (name === "password" && nextForm.passwordCheck) {
                nextErrors.passwordCheck = getFieldError("passwordCheck", nextForm);
            }

            return nextErrors;
        });
    }

    function validate() {
        const nextErrors = Object.fromEntries(
            Object.keys(EMPTY_ERRORS).map((name) => [
                name,
                getFieldError(name, form),
            ]),
        );
        setErrors(nextErrors);
        return !Object.values(nextErrors).some(Boolean);
    }

    async function handleSubmit(event) {
        event.preventDefault();
        if (!validate()) {
            return;
        }

        try {
            setIsSubmitting(true);
            await userApi.updatePassword(form);
            authStorage.removeAccessToken();
            navigate("/login", { replace: true });
        } catch (error) {
            if (hasErrorCode(error, "INVALID_CURRENT_PASSWORD")) {
                setErrors((previous) => ({
                    ...previous,
                    currentPassword: getErrorMessage(error),
                }));
            } else {
                setErrors((previous) => ({
                    ...previous,
                    passwordCheck: getErrorMessage(error, "비밀번호 수정에 실패했습니다."),
                }));
            }
        } finally {
            setIsSubmitting(false);
        }
    }

    return (
        <PageLayout
            pageClassName="password-edit-page"
            mainClassName="password-edit-section"
            title="계정 보안"
            showBack
            backTo="/posts"
        >
            <h2 className="password-edit-title">비밀번호 수정</h2>
            <InfoBanner
                eyebrow="Security"
                title="대나무숲 계정을 안전하게 보호하세요"
                description="글과 댓글을 편안하게 관리할 수 있도록 비밀번호를 새롭게 설정하세요."
            />
            <ErrorBoundary fallback={<p>비밀번호 수정 양식을 표시하지 못했습니다.</p>}>
                <PasswordEditForm
                    form={form}
                    errors={errors}
                    isValid={isFormValid}
                    isSubmitting={isSubmitting}
                    onChange={handleChange}
                    onSubmit={handleSubmit}
                />
            </ErrorBoundary>
        </PageLayout>
    );
}

export default PasswordEditPage;
```

## 15.24 모범 답안과 오답 정리

### 1번

- 모범 답안: `post`는 제목·내용·상태를, `comments`는 댓글 추가·수정·삭제를 담당하는 배열입니다. 댓글 변경 때 전체 post object를 다시 만들지 않고 댓글 배열만 불변 갱신하기 위해 분리합니다.

### 2번

- 모범 답안: 프론트 조건은 버튼 표시·사용성만 제어하며, 사용자는 API를 직접 호출하거나 오래된 화면을 사용할 수 있습니다. 최종 권한·신고 기준·활성 상태는 backend Service가 검사해야 합니다.
- 오답 포인트: 버튼이 숨겨졌으므로 보안이 끝났다고 보면 안 됩니다.

### 3번

- 오답 포인트: ref 값만 바꾸면 React가 버튼을 다시 그린다고 보면 안 됩니다.

### 7번

- 모범 답안: 새 이미지 Data URL은 아직 서버에 저장되지 않은 pending 값이고 previewUrl은 저장 전 즉시 미리보기와 PageLayout header에 사용할 표시값입니다. 저장 성공 후 pending 값을 비울 수 있습니다.
- 오답 포인트: preview URL이 곧 DB 저장 완료를 뜻한다고 보면 안 됩니다.

### 8번

- 모범 답안: backend는 비밀번호 변경 후 refresh session을 revoke하고, 프론트도 기존 access token을 계속 보내지 않도록 제거합니다. 이후 새 비밀번호로 다시 로그인하게 합니다.
- 오답 포인트: token 삭제만으로 backend 비밀번호가 바뀌거나 session revoke가 실행된다고 보면 안 됩니다.

### 9번

- 모범 답안: `field.name`이 `currentPassword`, `password`, `passwordCheck` 중 하나이므로 `form[field.name]`과 `errors[field.name]`이 같은 이름의 값을 읽습니다. 하나의 form handler와 반복 JSX를 공유할 수 있습니다.
- 오답 포인트: errors가 배열 index로 연결된다고 보면 실제 object key 구조와 다릅니다.

### 10번

- 모범 답안: 프론트는 조회 당시 `version`과 title·content·imageFiles를 보내고, 백엔드 `PostService.fixPost()`가 현재 Entity와 비교합니다. 세 값이 같으면 아무 변경 없이 응답하고 version을 올리지 않습니다. 제목·내용이 같고 이미지만 다르면 `OPTIMISTIC_FORCE_INCREMENT` 후 이미지를 바꾸며, 제목이나 내용이 다르면 일반 `@Version` 낙관적 충돌 검사가 적용됩니다. 현재 `isFixed` field는 Entity·response·migration 후 schema에서 제거되었습니다.
- 오답 포인트: `isFixed=true`가 수정 여부를 저장하거나 프론트가 수정 여부를 계산한다고 설명하면 현재 코드와 맞지 않습니다.
