# 3단계. 이미지 검증과 예외 응답

## 최신 코드 변경 반영 범위

현재 백엔드의 `오류 메시지 수정` 커밋을 기준으로 다음 번호를 다시 확인해야 한다.

1. **8번**: `GlobalExceptionHandler`가 각 Handler에서 직접 DTO를 만들지 않고 공통 `error(...)` 메서드를 호출하도록 변경되었다.
2. **10번**: `ErrorResponseDto`가 `message`만 반환하지 않고 `code`, `message`, `status`를 함께 반환한다.
3. **11번**: `ApiErrorCode` enum이 raw 오류 code를 표준 code와 사용자 문구로 변환한다.
4. **12번**: `ErrorResponseWriter`가 Security Filter·Interceptor에서 JSON 오류 응답을 직접 작성한다.
5. **13번**: `JwtAuthenticationFilter`와 `SessionOriginInterceptor`가 새 Writer를 통해 오류를 반환한다.
6. **14번**: 프론트 `api.js`는 서버 응답의 `data.code`, `data.message`, HTTP status를 Error 객체에 복사한다.

아래 개정판의 8~14번이 현재 실제 코드 기준이며, 기존 8~11번 설명은 변경 전 코드의 흐름을 보존한 참고 내용이다.

~~~java
package kr.adapterz.springdatajpa.validation; // 이 class가 속한 package다.

import kr.adapterz.springdatajpa.exception.InvalidRequestException;

import java.nio.charset.StandardCharsets;
import java.util.Base64;
import java.util.List;
import java.util.Set;

public final class ImageDataUrlValidator { // 상태를 만들지 않는 검증 utility이며 상속도 막는다.
    public static final int MAX_POST_IMAGE_COUNT = 3; // 게시글 전체 이미지 개수의 상한이다.
    public static final int MAX_IMAGE_BYTES = 3 * 1024 * 1024; // 이미지 하나의 decoded byte 상한이다.
    private static final int MAX_BASE64_LENGTH = // decoding 전 문자열 상한을 저장한다.
            ((MAX_IMAGE_BYTES + 2) / 3) * 4; // 3 byte가 4 Base64 문자로 변환되는 비율을 이용해 올림 계산한다.
    private static final Set<String> ALLOWED_IMAGE_TYPES = Set.of( // 허용 MIME 집합을 만든다.
            "image/jpeg", // JPEG를 허용한다.
            "image/png", // PNG를 허용한다.
            "image/webp", // WebP를 허용한다.
            "image/gif" // GIF를 허용한다.
    ); // Set.of 호출을 끝낸다.

    private ImageDataUrlValidator() { // 외부에서 utility 객체를 생성하지 못하게 한다.
    } // private constructor의 본문이다.

    // 호출 위치: PostService의 게시글 작성·수정
    public static void validatePostImages(List<String> imageFiles) { // PostService가 이미지 목록 검증을 시작하는 public 진입점이다.
        if (imageFiles == null) { // 이미지 미첨부인지 확인한다.
            return; // 선택 입력인 null은 정상으로 끝낸다.
        }
        if (imageFiles.size() > MAX_POST_IMAGE_COUNT) { // 항목 수가 3개를 초과하는지 확인한다.
            throw new InvalidRequestException("Too_Many_Images"); // 초과하면 Service 저장 흐름을 중단한다.
        }
        for (String imageFile : imageFiles) { // 목록의 각 Data URL을 순서대로 꺼낸다.
            validateImage(imageFile); // 이미지 하나의 형식·크기·signature 검사를 호출한다.
        }
    }

    // 호출 위치: UserService의 회원가입·회원정보 수정
    public static void validateProfileImage(String profileImage) { // UserService가 단일 profile image를 검증하는 진입점이다.
        if (profileImage == null) { // 프로필 이미지가 없는지 확인한다.
            return; // 선택 입력이면 정상 종료한다.
        }
        validateImage(profileImage); // 목록 개수 검사 없이 공통 단일 이미지 검사로 이동한다.
    }

    // 공통 검증 구간: 위 두 public method가 모두 여기로 들어온다.
    private static void validateImage(String dataUrl) { // 두 public method가 공유하는 실제 검증 함수다.
        if (dataUrl == null || dataUrl.isBlank()) { // null·빈 문자열·공백 문자열을 거부한다.
            throw new InvalidRequestException("Invalid_Image_Data"); // 외부 응답용 프로젝트 오류 code로 변환한다.
        }
        int separatorIndex = dataUrl.indexOf(','); // Data URL header와 Base64 본문의 구분 위치를 찾는다.
        if (separatorIndex <= 5) { // 쉼표가 없거나 header가 지나치게 짧은 경우를 거부한다.
            throw new InvalidRequestException("Invalid_Image_Data"); // 구조 오류를 업무 예외로 전파한다.
        }
        String header = dataUrl.substring(0, separatorIndex); // 쉼표 앞 data:image/...;base64 부분을 자른다.
        String mimeType = extractMimeType(header); // header에서 image/png 같은 MIME만 추출한다.
        String encodedData = dataUrl.substring(separatorIndex + 1); // 쉼표 뒤 Base64 본문만 자른다.
        if (!ALLOWED_IMAGE_TYPES.contains(mimeType)) { // MIME이 허용 Set에 포함되는지 확인한다.
            throw new InvalidRequestException("Unsupported_Image_Type"); // 허용되지 않은 형식이면 중단한다.
        }
        if (encodedData.length() > MAX_BASE64_LENGTH) { // decoding 전에 지나치게 긴 문자열을 차단한다.
            throw new InvalidRequestException("Image_Too_Large"); // 메모리 사용 전에 크기 오류를 전파한다.
        }
        byte[] imageBytes; // decoding 결과를 담을 byte 배열 변수를 선언한다.
        try { // Base64 library 예외를 프로젝트 예외로 바꿀 범위다.
            imageBytes = Base64.getDecoder().decode(encodedData); // 문자열을 실제 이미지 byte로 변환한다.
        } catch (IllegalArgumentException exception) { // 잘못된 Base64가 발생시킨 library 예외를 잡는다.
            throw new InvalidRequestException("Invalid_Image_Data"); // library 세부 예외를 외부 code로 통일한다.
        }
        if (imageBytes.length > MAX_IMAGE_BYTES) { // decoding 후 실제 byte 크기를 다시 확인한다.
            throw new InvalidRequestException("Image_Too_Large"); // 실제 파일이 크면 중단한다.
        }
        if (!hasMatchingSignature(mimeType, imageBytes)) { // 선언 MIME과 실제 시작 byte가 맞는지 확인한다.
            throw new InvalidRequestException("Invalid_Image_Data"); // signature가 다르면 중단한다.
        }
    }

    private static String extractMimeType(String header) { // Data URL header만 담당하는 private 함수다.
        if (!header.startsWith("data:") || !header.endsWith(";base64")) { // header 양끝의 고정 형식을 확인한다.
            throw new InvalidRequestException("Invalid_Image_Data"); // Data URL이 아니면 중단한다.
        }
        return header.substring("data:".length(), header.length() - ";base64".length()); // 양끝을 제외한 MIME 문자열을 반환한다.
    }

    private static boolean hasMatchingSignature(String mimeType, byte[] bytes) { // MIME별 magic byte 검사의 결과를 반환한다.
        return switch (mimeType) { // MIME 값에 맞는 검사 branch를 값으로 반환한다.
            case "image/jpeg" -> startsWith(bytes, new int[]{0xFF, 0xD8, 0xFF}); // JPEG signature를 확인한다.
            case "image/png" -> startsWith(bytes, new int[]{0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A}); // PNG 8 byte signature를 확인한다.
            case "image/gif" -> startsWithText(bytes, "GIF87a") || startsWithText(bytes, "GIF89a"); // 두 GIF header 중 하나인지 확인한다.
            case "image/webp" -> startsWithText(bytes, "RIFF") && hasTextAt(bytes, "WEBP", 8); // WebP container 표식을 두 위치에서 확인한다.
            default -> false; // 허용 목록 밖 MIME은 일치하지 않는 것으로 처리한다.
        };
    }

    private static boolean startsWith(byte[] bytes, int[] signature) { // 숫자 signature와 byte 배열 앞부분을 비교한다.
        if (bytes.length < signature.length) { // 비교할 실제 byte가 충분한지 먼저 확인한다.
            return false; // 짧으면 일치할 수 없다.
        }
        for (int index = 0; index < signature.length; index++) { // signature 각 위치를 순회한다.
            if ((bytes[index] & 0xFF) != signature[index]) { // signed byte를 0~255로 바꿔 예상값과 비교한다.
                return false; // 한 byte라도 다르면 불일치다.
            }
        }
        return true; // 모든 위치가 같으면 일치다.
    }

    private static boolean startsWithText(byte[] bytes, String text) { // 문자열 signature를 offset 0에서 검사한다.
        return hasTextAt(bytes, text, 0); // 공통 offset 검사 함수에 위임한다.
    }

    private static boolean hasTextAt(byte[] bytes, String text, int offset) { // 지정 offset의 ASCII 문자열을 검사한다.
        byte[] expected = text.getBytes(StandardCharsets.US_ASCII); // 비교 문자열을 ASCII byte 배열로 바꾼다.
        if (bytes.length < offset + expected.length) { // offset부터 문자열 전체를 비교할 길이가 있는지 확인한다.
            return false; // 길이가 부족하면 불일치다.
        }
        for (int index = 0; index < expected.length; index++) { // 예상 문자열의 각 byte를 순회한다.
            if (bytes[offset + index] != expected[index]) { // 실제 offset 위치와 예상 byte를 비교한다.
                return false; // 하나라도 다르면 불일치다.
            }
        }
        return true; // 모든 byte가 같으면 해당 위치에 문자열이 있다.
    }
}
~~~

## 1-목차. ImageDataUrlValidator 위치 주석본

~~~java
package kr.adapterz.springdatajpa.validation;

import kr.adapterz.springdatajpa.exception.InvalidRequestException;

import java.nio.charset.StandardCharsets;
import java.util.Base64;
import java.util.List;
import java.util.Set;

//1
public final class ImageDataUrlValidator {

    //3
    public static final int MAX_POST_IMAGE_COUNT = 3;
    public static final int MAX_IMAGE_BYTES = 3 * 1024 * 1024;

    private static final int MAX_BASE64_LENGTH =
            ((MAX_IMAGE_BYTES + 2) / 3) * 4;

    private static final Set<String> ALLOWED_IMAGE_TYPES = Set.of(
            "image/jpeg",
            "image/png",
            "image/webp",
            "image/gif"
    );

    private ImageDataUrlValidator() {
    }

    //2
    public static void validatePostImages(List<String> imageFiles) {
        if (imageFiles == null) {
            return;
        }

        if (imageFiles.size() > MAX_POST_IMAGE_COUNT) {
            throw new InvalidRequestException("Too_Many_Images");
        }

        for (String imageFile : imageFiles) {
            validateImage(imageFile);
        }
    }

    //2
    public static void validateProfileImage(String profileImage) {
        if (profileImage == null) {
            return;
        }

        validateImage(profileImage);
    }

    //4
    private static void validateImage(String dataUrl) {
        if (dataUrl == null || dataUrl.isBlank()) {
            throw new InvalidRequestException("Invalid_Image_Data");
        }

        int separatorIndex = dataUrl.indexOf(',');
        if (separatorIndex <= 5) {
            throw new InvalidRequestException("Invalid_Image_Data");
        }

        String header = dataUrl.substring(0, separatorIndex);
        String mimeType = extractMimeType(header);
        String encodedData = dataUrl.substring(separatorIndex + 1);

        if (!ALLOWED_IMAGE_TYPES.contains(mimeType)) {
            throw new InvalidRequestException("Unsupported_Image_Type");
        }

        if (encodedData.length() > MAX_BASE64_LENGTH) {
            throw new InvalidRequestException("Image_Too_Large");
        }

        byte[] imageBytes;
        try {
            imageBytes = Base64.getDecoder().decode(encodedData);
        } catch (IllegalArgumentException exception) {
            throw new InvalidRequestException("Invalid_Image_Data");
        }

        if (imageBytes.length > MAX_IMAGE_BYTES) {
            throw new InvalidRequestException("Image_Too_Large");
        }

        if (!hasMatchingSignature(mimeType, imageBytes)) {
            throw new InvalidRequestException("Invalid_Image_Data");
        }
    }

    //5
    private static String extractMimeType(String header) {
        if (!header.startsWith("data:") || !header.endsWith(";base64")) {
            throw new InvalidRequestException("Invalid_Image_Data");
        }

        return header.substring("data:".length(), header.length() - ";base64".length());
    }

    //6
    private static boolean hasMatchingSignature(String mimeType, byte[] bytes) {
        return switch (mimeType) {
            case "image/jpeg" -> startsWith(bytes, new int[]{0xFF, 0xD8, 0xFF});
            case "image/png" -> startsWith(
                    bytes,
                    new int[]{0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A}
            );
            case "image/gif" -> startsWithText(bytes, "GIF87a")
                    || startsWithText(bytes, "GIF89a");
            case "image/webp" -> startsWithText(bytes, "RIFF")
                    && hasTextAt(bytes, "WEBP", 8);
            default -> false;
        };
    }

    //6
    private static boolean startsWith(byte[] bytes, int[] signature) {
        if (bytes.length < signature.length) {
            return false;
        }

        for (int index = 0; index < signature.length; index++) {
            if ((bytes[index] & 0xFF) != signature[index]) {
                return false;
            }
        }

        return true;
    }

    //6
    private static boolean startsWithText(byte[] bytes, String text) {
        return hasTextAt(bytes, text, 0);
    }

    //6
    private static boolean hasTextAt(byte[] bytes, String text, int offset) {
        byte[] expected = text.getBytes(StandardCharsets.US_ASCII);
        if (bytes.length < offset + expected.length) {
            return false;
        }

        for (int index = 0; index < expected.length; index++) {
            if (bytes[offset + index] != expected[index]) {
                return false;
            }
        }

        return true;
    }
}
~~~

실제 검색 결과:

- UserService 회원가입: validateProfileImage(request.getProfileImage())

따라서 이 class는 파일을 저장하지 않는다. 입력 문자열이 정책을 통과하는지만 확인하고, 실패하면 InvalidRequestException을 던진다. 저장과 transaction은 호출한 Service가 담당한다.

## 3. 선언부와 상수

- final class: 상속을 허용하지 않는 class다. 이 class는 상태를 가진 객체가 아니라 static utility다.
- MAX_POST_IMAGE_COUNT: 게시글 image list의 최대 항목 수다.
- MAX_IMAGE_BYTES: decoded image 한 장의 최대 byte다. 3 * 1024 * 1024는 3 MiB다.
- MAX_BASE64_LENGTH: decoding 전에 지나치게 긴 입력을 차단하기 위한 예상 문자열 상한이다.
- Set.of: 허용 MIME type을 중복 없는 Set으로 만든다.
- private constructor: 외부에서 new하지 못하게 한다. 호출자는 class 이름으로 static method를 호출한다.

## 4. public method 실행 흐름

### validatePostImages

1. null이면 이미지 미첨부로 보고 정상 종료한다.
2. list size가 3보다 크면 Too_Many_Images를 던진다.
3. for-each로 각 Data URL을 꺼낸다.
4. 각 항목을 private validateImage에 전달한다.

for-each는 collection의 요소를 처음부터 끝까지 순회하는 문법이다. imageFile 변수는 현재 순회 중인 단 하나의 문자열이다.

### validateProfileImage

1. null이면 선택 입력이므로 정상 종료한다.
2. 값이 있으면 validateImage 하나만 호출한다.

두 public method가 같은 private method를 공유하므로 profile image와 post image의 “이미지 하나” 규칙은 동일하다.

## 5. validateImage 실행 순서

1. dataUrl이 null이거나 blank인지 확인한다.
2. indexOf(',')로 Data URL header와 Base64 body를 나눈다.
3. substring으로 header와 encodedData를 각각 추출한다.
4. extractMimeType에서 data: 시작과 ;base64 끝을 확인한다.
5. Set.contains로 허용 MIME인지 검사한다.
6. decoding 전에 encodedData 길이를 검사한다.
7. Base64 decoder로 byte 배열을 만든다.
8. 잘못된 Base64의 IllegalArgumentException을 InvalidRequestException으로 변환한다.
9. 실제 decoded byte 길이를 다시 검사한다.
10. MIME에 맞는 magic byte인지 검사한다.

substring의 끝 index는 포함하지 않는다. separatorIndex가 쉼표 위치이므로 substring(0, separatorIndex)는 쉼표 앞 header만 가져온다.

Base64 문자열 길이와 decoded byte 길이를 둘 다 검사하는 이유는, 문자열 길이만으로 실제 byte 크기를 정확히 확정할 수 없기 때문이다. 앞의 검사는 decoding 전 메모리 사용을 제한하고, 뒤의 검사가 실제 크기의 최종 기준이다.

## 6. signature 검사에 사용된 문법

hasMatchingSignature는 switch expression으로 MIME별 결과를 반환한다.

- JPEG: FF D8 FF
- PNG: 표준 8 byte signature
- GIF: GIF87a 또는 GIF89a
- WebP: offset 0의 RIFF와 offset 8의 WEBP

startsWith는 byte 배열과 int 배열을 비교한다. Java byte는 signed이므로 bytes[index] & 0xFF로 0~255 범위로 바꾼 뒤 비교한다. &는 bitwise AND 연산자다.

startsWithText는 문자열을 ASCII byte로 변환한 뒤 hasTextAt(bytes, text, 0)을 호출한다. WebP는 offset 8을 전달한다.

이 검사는 파일 전체를 해석하거나 antivirus 검사를 하는 것이 아니다. 허용 MIME과 기본 signature가 일치하는지만 확인한다.

## 7. 예외 class 전체 원문

파일: exception/InvalidRequestException.java

~~~java
public class InvalidRequestException extends RuntimeException {

    // 예외 code를 전달받아 부모 RuntimeException에 저장한다.
    public InvalidRequestException(String message) {
        super(message); // getMessage()가 이 code를 반환하도록 부모 생성자를 호출한다.
~~~

- extends: RuntimeException의 기능을 상속한다.
- 생성자 message: validator가 Too_Many_Images 같은 오류 code를 전달한다.
- super(message): 부모 exception의 message로 저장한다.
- RuntimeException: Service method가 checked exception 선언을 반복하지 않아도 호출 stack을 따라 전파된다.

## 9. Handler의 연결 원리

- RestControllerAdvice: 여러 Controller에 공통 적용되는 advice Bean이다. 예외를 발생시키지 않는다.
- ExceptionHandler(X.class): 실제 예외가 X이면 아래 method를 선택하는 연결 metadata다.
- ResponseEntity<ErrorResponseDto>: HTTP status와 body 객체를 함께 반환한다.
- ResponseEntity.status(...).body(...): builder chain으로 status와 body를 순서대로 설정한다.
- e.getMessage(): Service가 넣은 오류 code를 DTO에 복사한다.
- MethodArgumentNotValidException: DTO annotation 실패다. 현재 구현은 field별 상세 오류를 버리고 invalid_request만 반환한다.
- 두 예외 처리: 하나의 Handler 메서드가 `PostVersionConflictException`과 `ObjectOptimisticLockingFailureException`을 모두 처리한다.

실제 예:

~~~text
UserService
→ throw new InvalidRequestException("Existed_Email")
→ Spring MVC가 GlobalExceptionHandler 탐색
→ handleInvalidRequestException 선택
→ HTTP 400 + ErrorResponseDto(message="Existed_Email")
→ JSON body
~~~

Security Filter에서 직접 작성한 401/403 응답은 이 Handler를 거치지 않는다. 이 Handler는 Controller 호출 흐름으로 전파된 예외를 대상으로 한다.

## 11. 프론트 오류 code 연결

파일: src/utils/errorMessage.js

api.js의 createRequestError는 Error 객체에 code, status, data를 추가한다. errorMessage.js는 다음 순서로 화면 문구를 선택한다.

~~~javascript
export function getErrorCode(error) { // 전달된 오류 객체에서 화면 표시용 오류 code를 추출한다.
    if (typeof error === "string") { // 오류 자체가 문자열이면 그 문자열을 code로 사용한다.
        return error; // 문자열 오류를 그대로 반환한다.
    }
    if (typeof error?.code === "string") { // Error 객체에 문자열 code가 있으면 우선 사용한다.
        return error.code; // api.js가 추가한 code를 반환한다.
    }
    if (typeof error?.data?.message === "string") { // 서버 JSON의 data.message를 다음 후보로 확인한다.
        return error.data.message; // 백엔드 ErrorResponseDto의 message를 반환한다.
    }
    return typeof error?.message === "string" ? error.message : ""; // 남은 Error message가 없으면 빈 문자열을 반환한다.
}

export function getErrorMessage( // 오류 객체를 사용자에게 보여줄 문구로 변환한다.
    error, // API 요청 실패에서 전달된 오류다.
    fallback = "요청 처리에 실패했습니다. 잠시 후 다시 시도해주세요.", // 대응 문구가 없을 때 사용할 기본 문구다.
) {
    const code = getErrorCode(error); // 먼저 오류 code를 추출한다.
    return ( // 가장 구체적인 문구부터 순서대로 선택한다.
        ERROR_CODE_MESSAGES[code] // 백엔드 오류 code에 대응하는 문구를 찾는다.
        ?? STATUS_MESSAGES[error?.status] // code가 없으면 HTTP status 문구를 찾는다.
        ?? fallback // 둘 다 없으면 기본 문구를 사용한다.
    );
}
~~~

- typeof: JavaScript 값의 type을 확인한다.
- optional chaining error?.code: error가 null이어도 접근 오류를 내지 않는다.
- rest parameter ...codes가 있는 hasErrorCode는 여러 code를 받을 수 있다.
- object lookup ERROR_CODE_MESSAGES[code]는 code에 대응하는 한국어 문구를 찾는다.
- nullish coalescing은 code 문구가 없을 때 status 문구, 그것도 없을 때 fallback을 사용한다.

회원가입의 Existed_Email은 SignupPage catch에서 getErrorMessage를 거쳐 email field에 표시된다. 같은 방식으로 Already_Liked, Post_Version_Conflict 등의 문구도 선택된다.

```java
import com.fasterxml.jackson.databind.ObjectMapper;
import jakarta.servlet.http.HttpServletResponse;
import kr.adapterz.springdatajpa.dto.ErrorResponseDto;
```

`CannotAcquireLockException`을 넣어 status 503과 code를 확인하지만, 실제 MySQL deadlock이나
