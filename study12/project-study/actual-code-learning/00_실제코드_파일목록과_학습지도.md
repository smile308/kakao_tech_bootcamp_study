## 진행률 기준

전체 학습 단계를 14개로 나누어 계산한다. 파일 목록과 지도는 별도 준비 단계이며, 실제 흐름 문서가 완성된 단계만 진행률에 포함한다.

| 단계 | 상태 |
|---|---|
| 0. 파일 목록·학습 지도 | 완료 |
| 1. 빌드·profile·Spring Boot 시작 | 완료 |
| 2. 회원가입 | 완료 |
| 3. 검증·예외 응답 | 완료 |
| 4. 로그인·인증 — Session DTO·JwtProvider | 1차 묶음 완료 |
| 4. 로그인·인증 — Refresh Token·AuthSession 이후 | 대기 |
| 5~14 | 대기 |

현재 위치: **14개 큰 묶음 중 4번 인증 묶음의 첫 번째 파일 묶음 완료**

이 숫자는 전체 코드의 29%를 봤다는 뜻이 아니다. 백엔드 관련 파일 133개와 프론트/배포 관련 파일 80개를 합쳐 최소 213개 파일이 학습 대상이며, 각 파일은 정독·연결 확인·중복 스킵 판정을 따로 해야 한다.

실제 파일 진행률은 앞으로 다음 세 가지로 기록한다.

- 정독 완료 파일 수
- 호출 관계만 확인한 파일 수
- 중복 근거를 확인하고 스킵한 파일 수

문서 단계가 끝났다는 이유만으로 전체 파일 진행률을 올리지 않는다.

현재 파일 집계: **21개 확인 완료 / 최소 학습 대상 213개 = 약 9.9%**

이 수치는 문서에 실제 원문을 확인하고 설명한 파일만 중복 제거해 계산했다. `authApi`와 `api.js`처럼 일부 호출 코드만 언급하고 전체 파일을 정독하지 않은 파일은 포함하지 않았다.

각 단계는 파일 전체를 훑은 뒤, 실제 호출 관계와 반환값을 확인하고 다음 단계로 이동한다. 같은 문법을 만났다는 이유만으로 파일을 생략하지 않고, “완전히 동일한 구조인지” 확인한 뒤 스킵한다.

각 코드 묶음은 `전체 주석본`을 먼저 제시하고, 바로 뒤에 같은 실제 코드를 `목차 주석본`으로 다시 제시한다. 전체 주석본에는 호출 위치·실행 구간·변수 역할·예외 경로를 설명하는 주석을 직접 달고, 목차 주석본에는 설명 번호의 앞번호만 `//3`처럼 표시한다. 한 코드가 여러 설명 항목에 해당하면 `//2,4`처럼 번호를 합쳐 표시하고, 같은 번호를 코드 줄마다 반복하지 않는다. `package`와 `import` 줄에는 주석을 달지 않으며, 목차 주석본에는 설명 문장을 넣지 않는다.

## 기능별 최종 흐름

- 회원가입: SignupForm → authApi → api.js → UserController → UserRequestDto → UserService → UserRepository/User → UserResponseDto → JSON → 화면
- 로그인: LoginForm → authApi → SessionController → SessionService → AuthenticationManager/UserDetailsService → JwtProvider/RefreshTokenProvider → AuthSessionRepository → Cookie/body

- 게시글 목록: PostsPage → postApi → api.js → PostController → PostService → PostRepository/Pageable → Page DTO → state/observer
- 조회수: 상세 화면 → PostService/view updater → Redis key/dirty set → flush scheduler → PostViewCountRepository
- 배포: GitHub Actions → image → SSM → deploy script → Compose → health → Nginx blue/green

## 현재 코드에서 확인된 핵심 의존 관계

아래 연결은 import와 실제 method 호출을 검색해 확인한 시작 지도다. 이후 각 흐름 문서에서 호출 method와 반환값을 다시 원문으로 대조한다.

~~~text
SpringdatajpaApplication
├─ @ConfigurationPropertiesScan → ViewCountProperties
├─ @EnableScheduling → RedisViewCountFlushScheduler/AuthSessionCleanupScheduler
└─ @SpringBootApplication → component scan

UserController
└─ UserService
   ├─ UserRepository
   ├─ PasswordEncoder
   └─ ImageDataUrlValidator

SessionController
└─ SessionService
   ├─ AuthenticationManager/CustomUserDetailsService
   ├─ JwtProvider
   ├─ RefreshTokenProvider
   ├─ RefreshCookieProvider
   └─ AuthSessionRepository

PostController
└─ PostService
   ├─ PostRepository/CommentRepository/LikeRepository/PostReportRepository
   ├─ ImageDataUrlValidator
   └─ ViewCountUpdater

frontend Page
└─ feature API module
   └─ api.js request()
      └─ fetch()
~~~

이 지도에 없는 파일은 아직 “사용되지 않음”으로 결론내리지 않는다. route, 문자열 이름, reflection, Spring annotation, workflow 참조는 단순 import 검색만으로 놓칠 수 있으므로 해당 단계에서 별도로 확인한다.

## 스킵 기준

- 예외 class: 첫 `RuntimeException` 상속과 생성자에서 문법을 설명하고 나머지는 사용 위치/status만 확인한다.
- DTO: 첫 Request/Response DTO에서 annotation, getter, 생성자를 설명하고 나머지는 field/호출 위치만 확인한다.
- 공통 UI: props/JSX/callback이 동일하면 실제 사용처와 표시 차이만 본다.
- CSS/asset/font: 코드 흐름에 새 개념이 없으면 import와 적용 위치만 확인한다.
- wrapper 내부: 고정된 Gradle 실행기라 프로젝트 업무 코드 흐름과 무관하다.
- 현재 참조되지 않는 파일: import, route, 문자열, workflow 참조를 검색한 뒤에만 “사용되지 않음”으로 표시한다.
