# 4장. 입력값 검증과 예외 처리

## 4.1 학습 목표

잘못된 요청이 어디서 발견되고 어떤 HTTP 응답으로 변환되어 프론트 화면까지 도달하는지 학습한다.

```text
잘못된 입력
→ DTO 검증 또는 Service 예외
→ GlobalExceptionHandler
→ HTTP 상태와 ErrorResponseDto
→ 프론트 request()
→ Error 객체
→ 화면 메시지
```

## 4.2 두 종류의 검증

DTO 선언 검증:

```java
@NotBlank
@Email
private String email;
```

업무 규칙 검증:

```java
if (userRepository.existsByEmailAndDeletedFalse(request.getEmail())) {
    throw new InvalidRequestException("Existed_Email");
}
```

```text
DTO 검증
→ 값의 형식과 기본 조건
→ 이메일 형식, 필수값, 길이

Service 검증
→ DB 상태와 업무 정책
→ 이메일 중복, 정지 계정, 소유권
```

## 4.3 실제 코드 발췌: 전역 예외 처리

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(InvalidRequestException.class)
    public ResponseEntity<ErrorResponseDto> handleInvalidRequestException(
            InvalidRequestException e
    ) {
        ErrorResponseDto response = new ErrorResponseDto(e.getMessage());

        return ResponseEntity
                .status(HttpStatus.BAD_REQUEST)
                .body(response);
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponseDto> handleValidationException(
            MethodArgumentNotValidException e
    ) {
        ErrorResponseDto response =
                new ErrorResponseDto("invalid_request");

        return ResponseEntity
                .status(HttpStatus.BAD_REQUEST)
                .body(response);
    }

    @ExceptionHandler(AuthException.class)
    public ResponseEntity<ErrorResponseDto> handleAuthException(
            AuthException e
    ) {
        ErrorResponseDto response = new ErrorResponseDto(e.getMessage());

        return ResponseEntity
                .status(HttpStatus.UNAUTHORIZED)
                .body(response);
    }

    @ExceptionHandler(DataNullException.class)
    public ResponseEntity<ErrorResponseDto> handleDataNullException(
            DataNullException e
    ) {
        ErrorResponseDto response = new ErrorResponseDto(e.getMessage());

        return ResponseEntity
                .status(HttpStatus.NOT_FOUND)
                .body(response);
    }
}
```

위 코드는 실제 파일에서 대표 처리 메서드만 골라 동작 순서가 바뀌지 않도록 정리한 발췌본이다. 실제 파일에는 이 밖의 예외 처리 메서드와 작성된 주석도 있다.

중요한 줄:

```java
@RestControllerAdvice
// 모든 RestController에서 던진 예외를 공통으로 처리한다.

@ExceptionHandler(InvalidRequestException.class)
// 이 타입의 예외가 위로 전파되면 해당 메서드가 처리한다.

ResponseEntity.status(HttpStatus.BAD_REQUEST).body(response)
// HTTP 상태와 JSON 응답 본문을 함께 만든다.
```

## 4.4 HTTP 상태 매핑

이 프로젝트의 주요 매핑은 다음과 같다.

| 상황 | 예외 또는 처리 위치 | 상태 |
|---|---|---:|
| DTO 형식 실패 | `MethodArgumentNotValidException` | 400 |
| 잘못된 업무 요청 | `InvalidRequestException` | 400 |
| 로그인 실패·토큰 오류 | `LoginFailedException`, `AuthException` | 401 |
| 로그인했지만 권한 없음 | `ForbiddenException` | 403 |
| 데이터 없음 | `DataNullException` | 404 |
| 게시글 버전 충돌 | 낙관적 락 예외 | 409 |
| 카운터 갱신 실패 | `CounterUpdateException` | 500 |

401과 403을 구분한다.

```text
401 Unauthorized
→ 유효한 인증 정보가 없음

403 Forbidden
→ 인증은 되었지만 해당 행동 권한이 없음
```

## 4.5 실제 코드 발췌: 오류 응답 DTO

```java
@Getter
public class ErrorResponseDto {

    private String message;

    public ErrorResponseDto(String message) {
        this.message = message;
    }
}
```

예외 메시지 `"Existed_Email"`은 다음 JSON이 된다.

```json
{
  "message": "Existed_Email"
}
```

## 4.6 실제 코드 발췌: 프론트 오류 변환

```javascript
function createRequestError(response, data) {
    const errorMessage =
        typeof data === "string"
            ? data
            : data?.message ?? "요청 처리에 실패했습니다.";

    const error = new Error(errorMessage);
    error.code = errorMessage;
    error.status = response.status;
    error.data = data;
    return error;
}
```

중요한 줄:

```javascript
error.status = response.status;
// 화면 코드가 400, 401, 404 같은 상태를 구분할 수 있게 한다.

error.data = data;
// 서버가 반환한 원래 데이터를 보존한다.
```

공통 `request()`가 `response.ok`를 검사한 뒤 실패 응답을 JavaScript `Error`로 바꿔 던진다. Page의 `try/catch`가 이를 받아 `ErrorView`나 Toast에 표시한다.

## 4.7 ErrorBoundary와 API 오류의 차이

```text
API가 400/500 응답
→ fetch 자체는 Response를 반환
→ request()가 Error로 변환
→ Page의 catch에서 처리

React 렌더링 중 JavaScript 예외
→ ErrorBoundary가 fallback 화면 표시
```

API 오류라고 해서 자동으로 최상위 ErrorBoundary가 처리하는 것은 아니다.

```java
업무규칙위반이면 예외를 던진다.

전역예외처리기가
예외 타입 → HTTP 상태 + { message }
로 바꾼다.
```

```javascript

Page가 Error를 화면 메시지로 바꾼다.
```


## 4.8.1 전체 원문 코드 라인별 주석본

아래 주석은 학습을 위해 추가한 것이며 실제 프로젝트 파일에는 없다. 줄 끝 주석을 붙인 주석본은 의미를 따라가기 위한 설명용이므로 그대로 복사해 실행하지 않는다.

### DTO 검증과 Service 검증

```java
@NotBlank // 값이 없거나 공백만 있는 이메일을 Controller 진입 전에 거부한다.
@Email // 입력 문자열이 이메일 형식인지 검사한다.
private String email; // 검증이 적용되는 DTO 필드다.
```

```java
if (userRepository.existsByEmailAndDeletedFalse(request.getEmail())) { // 현재 DB 상태를 조회해야 알 수 있는 이메일 중복 업무 규칙이다.
    throw new InvalidRequestException("Existed_Email"); // 규칙 위반을 예외로 전파하여 저장 흐름을 즉시 중단한다.
}
```

### `GlobalExceptionHandler`

```java
@RestControllerAdvice // 모든 RestController에서 위로 전파된 예외를 공통 처리하는 Bean으로 등록한다.
public class GlobalExceptionHandler { // 예외 타입을 HTTP 응답으로 바꾸는 클래스를 선언한다.

    @ExceptionHandler(InvalidRequestException.class) // InvalidRequestException이 발생하면 아래 메서드를 선택한다.
    public ResponseEntity<ErrorResponseDto> handleInvalidRequestException( // 상태와 body를 함께 담은 HTTP 응답을 반환한다.
            InvalidRequestException e // 실제로 발생한 예외 객체를 받는다.
    ) {
        ErrorResponseDto response = new ErrorResponseDto(e.getMessage()); // 예외 메시지를 JSON 응답 DTO에 담는다.

        return ResponseEntity // ResponseEntity builder를 시작한다.
                .status(HttpStatus.BAD_REQUEST) // HTTP 상태를 400 Bad Request로 지정한다.
                .body(response); // ErrorResponseDto를 응답 body로 지정하고 완성한다.
    }

    @ExceptionHandler(MethodArgumentNotValidException.class) // @Valid DTO 검증 실패 예외를 처리한다.
    public ResponseEntity<ErrorResponseDto> handleValidationException( // 검증 실패용 HTTP 응답을 만드는 메서드다.
            MethodArgumentNotValidException e // 어떤 DTO 검증이 실패했는지 담은 예외를 받는다.
    ) {
        ErrorResponseDto response = // 공통 오류 응답 변수를 선언한다.
                new ErrorResponseDto("invalid_request"); // 현재 구현은 상세 필드 대신 고정 메시지를 응답한다.

        return ResponseEntity // 응답 builder를 시작한다.
                .status(HttpStatus.BAD_REQUEST) // 잘못된 입력이므로 400을 사용한다.
                .body(response); // 메시지 DTO를 JSON body로 반환한다.
    }

    @ExceptionHandler(AuthException.class) // Refresh Session 등 인증 검증 실패를 처리한다.
    public ResponseEntity<ErrorResponseDto> handleAuthException( // 인증 오류 응답을 만든다.
            AuthException e // 발생한 인증 예외를 받는다.
    ) {
        ErrorResponseDto response = new ErrorResponseDto(e.getMessage()); // 예외 메시지를 응답에 보존한다.

        return ResponseEntity // 응답 builder를 시작한다.
                .status(HttpStatus.UNAUTHORIZED) // 유효 인증이 없으므로 401을 지정한다.
                .body(response); // 오류 DTO를 body로 반환한다.
    }

    @ExceptionHandler(DataNullException.class) // 요청한 사용자나 게시글이 없을 때의 예외를 처리한다.
    public ResponseEntity<ErrorResponseDto> handleDataNullException( // 데이터 없음 응답을 만든다.
            DataNullException e // 발생한 데이터 없음 예외를 받는다.
    ) {
        ErrorResponseDto response = new ErrorResponseDto(e.getMessage()); // 어떤 데이터가 없는지 메시지에 담는다.

        return ResponseEntity // 응답 builder를 시작한다.
                .status(HttpStatus.NOT_FOUND) // 찾을 수 없으므로 404를 지정한다.
                .body(response); // 오류 DTO를 body로 반환한다.
    }
}
```

### `ErrorResponseDto`

```java
@Getter // Jackson과 다른 코드가 message getter를 사용할 수 있게 Lombok이 생성한다.
public class ErrorResponseDto { // 모든 오류 응답에서 공통으로 사용할 데이터 모양이다.
    private String message; // 프론트가 오류 종류를 구분할 문자열을 저장한다.

    public ErrorResponseDto(String message) { // 예외 메시지를 받아 DTO를 만드는 생성자다.
        this.message = message; // 전달받은 값을 필드에 저장한다.
    }
}
```

### 프론트 `createRequestError`

```javascript
function createRequestError(response, data) { // 실패한 HTTP Response와 파싱한 body를 JavaScript Error로 바꾼다.
    const errorMessage = // 최종 오류 메시지를 결정할 변수를 만든다.
        typeof data === "string" // 응답 body 자체가 문자열인지 확인한다.
            ? data // 문자열이면 그대로 오류 메시지로 사용한다.
            : data?.message ?? "요청 처리에 실패했습니다."; // JSON이면 message를 쓰고 없으면 기본 문구를 쓴다.

    const error = new Error(errorMessage); // 표준 JavaScript Error 객체를 만든다.
    error.code = errorMessage; // 프로젝트 화면 코드가 오류 종류로 사용할 code를 추가한다.
    error.status = response.status; // 400, 401 같은 HTTP 상태를 추가한다.
    error.data = data; // 서버가 반환한 원본 body도 디버깅과 추가 처리용으로 보존한다.
    return error; // Page의 catch로 전달할 완성된 Error를 반환한다.
}
```

## 4.9 스킵할 코드

예외 클래스 대부분은 `RuntimeException`을 상속하고 메시지를 전달하는 동일 구조다. 대표로 `InvalidRequestException` 하나를 이해한 뒤 다음 클래스는 사용 위치와 상태만 확인한다.

- `AuthException`
- `DataNullException`
- `ForbiddenException`
- `LoginFailedException`

`PostVersionConflictException`과 `CounterUpdateException`은 동시성 장에서 발생 이유를 다시 확인한다.


## 4.9.1 이 장에서 필요한 예외·응답 문법

### 상속과 `RuntimeException`

```java
public class InvalidRequestException
        extends RuntimeException
```

`extends`는 부모 클래스의 기능을 상속한다. 이 예외는 RuntimeException의 메시지와 stack trace 기능을 사용하면서 업무상 잘못된 요청이라는 별도 타입을 만든다.

RuntimeException은 checked exception과 달리 메서드 선언에 `throws`를 강제하지 않는다. Transaction 안에서 밖으로 전파되면 기본적으로 rollback 대상이 된다.

### `super`

```java
public InvalidRequestException(String message) {
    super(message);
}
```

`super(...)`는 부모 클래스 생성자를 호출한다. 전달한 message는 이후 `e.getMessage()`로 읽을 수 있다.

### Generic 응답 타입

```java
ResponseEntity<ErrorResponseDto>
```

HTTP 응답 body에 `ErrorResponseDto`가 들어간다는 Generic 표현이다. 상태·header·body를 함께 제어한다.

### Method chaining

```java
ResponseEntity
        .status(HttpStatus.BAD_REQUEST)
        .body(response);
```

앞 메서드가 다음 설정 메서드를 가진 객체를 반환하므로 점을 이어 호출한다. 호출 순서는 위에서 아래다.

### 여러 예외 타입 한 Handler에 연결

```java
@ExceptionHandler({
    AException.class,
    BException.class
})
```

중괄호는 Java 어노테이션의 배열 값이다. 두 예외 중 하나가 발생해도 같은 처리 메서드를 사용한다. `.class`는 객체가 아니라 클래스 타입 자체를 나타낸다.

### JavaScript 삼항 연산자

```javascript
condition ? valueWhenTrue : valueWhenFalse
```

`createRequestError`에서는 응답 body가 문자열이면 그대로 사용하고 아니면 JSON의 message를 사용한다.

### optional chaining과 nullish coalescing

```javascript
data?.message ?? "기본 메시지"
```

- `data?.message`: data가 null 또는 undefined면 오류를 내지 않고 undefined 반환
- `??`: 왼쪽이 null 또는 undefined일 때만 오른쪽 기본값 사용
- 빈 문자열이나 0은 `??`에서 유효한 값으로 유지된다.

### 객체에 동적 속성 추가

```javascript
const error = new Error(message);
error.status = response.status;
```

JavaScript 객체는 생성 뒤에도 속성을 추가할 수 있다. 표준 Error에 프로젝트가 필요한 `status`, `code`, `data`를 붙인다.
