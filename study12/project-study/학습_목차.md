# 프로젝트 전체 학습 목차

## 이 목차를 사용하는 방법

각 장은 앞 장에서 만든 흐름을 이어받는다. 장 안에서는 다음 순서로 공부한다.

```text
학습 목표와 실제 코드 읽기 순서
→ 주석 없는 실제 원문
→ 흐름 설명
→ 라인별 주석본
→ 문법 정리
→ 이해 확인 문제
→ 틀린 문제를 장 아래 오답노트에 기록
```

표시 Component, 단순 DTO, 예외 class처럼 이미 배운 구조가 그대로 반복되는 파일은 존재와 연결 위치만 확인한다. 반대로 API 호출, state 변경, transaction, lock, Redis, migration, test 범위, container 연결과 배포 순서는 반복처럼 보여도 기능 결과를 바꾸므로 스킵하지 않는다.

## 순서와 장별 도착점

| 순서 | 장 | 이 장을 마치면 설명할 수 있어야 하는 것 |
|---|---|---|
| 0 | 프로젝트 전체 실행 흐름 | React 시작부터 운영 Nginx·Spring까지 요청의 큰 경로 |
| 1 | Gradle 빌드와 의존성 | library가 들어오는 위치와 `test`·`redisTest`·`mysqlTest`·`check` 범위 |
| 2 | YAML과 실행 환경 | local·test·prod 설정, 환경변수, H2·RDS·Redis 선택 |
| 3 | 회원가입 backend 계층 | DTO → Controller → Service → Repository → Entity → response |
| 4 | 입력값 검증과 예외 처리 | 오류 발견 지점부터 HTTP error와 화면 메시지까지 |
| 5 | 로그인·JWT·Security | 로그인, 일반 인증 요청, Refresh Token 회전과 로그아웃 |

| 8 | 작성·댓글·회원정보 화면 연결 | backend API가 실제 Page state와 form에 연결되는 방식 |

## 장 사이의 핵심 연결

```text
0~3장: 코드를 읽기 위한 기본 지도

4~6장: 한 HTTP 요청의 backend 내부 처리

7~8장: 그 API를 사용하는 React state와 화면 처리

9~10장: Redis와 RDS에 데이터가 남는 방식

11장: 앞의 동작을 어느 범위까지 검증하는지

12~13장: 검증된 코드를 운영 환경에 실행하는 방식

14장: 기능·설정·운영 흐름을 한 번에 다시 연결
```

## 0~3장 재확인 범위

- 0장: 이번 문서 재구성으로 새로 공부해야 할 코드 내용은 없다. 이후 장의 위치가 바뀌었으므로 전체 목차만 이 파일 기준으로 본다.
- 1장: MySQL Testcontainers와 `mysqlTest`, `check` 연결이 추가되었다. `1.9 왜 Redis·MySQL 테스트를 분리하는가?`, `1.10 JaCoCo가 검사하는 범위`, `1.11 test와 check의 차이`만 다시 보면 된다.
- 2장: 새 개념은 추가하지 않았고 Flyway 상세 장 참조를 현재 10장으로 고쳤다.
- 3장: 새 개념은 추가하지 않았다.

따라서 1장을 이미 스킵하기로 했다면 지금 전부 다시 외울 필요는 없다. 11장에서 Gradle test task 연결이 이해되지 않을 때 위 세 절로 돌아오면 된다.
