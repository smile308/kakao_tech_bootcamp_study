작성일은 2026-08-11이다.

## 1. 작업 정보

- 기준 브랜치는 `develop`이다.
- 기준 커밋은 `94889305148519dd5c2ecb404cba69c1a5c0326e`이다.
- 작업 브랜치는 `codex/perf-owner1-http-stability`이다.
- 작업 범위는 로그인, 공통 HTTP 요청, 방 목록과 방 입장 전 단계, Tomcat 설정, 프로필 이미지 S3 전달이다.
- 담당자 2가 소유한 채팅방 입장 Socket 처리, 메시지 처리, 읽음 처리, 금칙어 처리 코드는 수정하지 않았다.
- 테스트 코드를 새로 만들거나 기존 테스트 코드를 수정하지 않았다.

## 2. 작업 배경

개선 전 부하테스트에서는 실제 생성 VU 160명 중 96명이 완료하고 64명이 실패했다. 주요 현상은 `toBeVisible` 실패 43건, 로그인 입력 `fill` timeout 14건, HTTP 502 3건, HTTP 504 171건이었다.

특히 로그인 화면은 `/api/health` 요청이 끝나기 전까지 입력 폼을 렌더링하지 않았다. 서버가 느려질수록 사용자가 입력할 DOM 자체가 늦게 나타나므로 로그인 입력 timeout과 직접 연결되는 구조였다. 또한 방 목록 조회 전에 health 요청을 먼저 실행했고, 공통 Axios 재시도와 화면별 health 재시도가 겹칠 수 있었다.

## 3. 적용한 개선

### 3.1 로그인 폼의 health gate 제거

로그인 입력 폼을 첫 렌더부터 표시하도록 변경했다. `/api/health`는 백그라운드 안내 문구를 갱신하는 용도로만 남겼다. health 요청이 지연되거나 실패해도 이메일과 비밀번호 입력, 로그인 요청, 회원가입 화면 이동을 막지 않는다.

기존 4초 fallback 화면과 health 성공 여부를 이용한 submit 차단도 제거했다. 실제 서버 접근 가능 여부는 로그인 API 응답으로 판단한다.

이 변경은 서버 부하 상황에서 로그인 입력 요소가 렌더링되지 않아 발생하던 `fill` timeout 원인을 코드 수준에서 제거한다.

### 3.2 health 선행 요청과 중복 요청 제거

방 목록을 가져오기 전에 실행하던 `/api/health` 선행 요청을 제거했다. 이제 최초 진입은 `/api/rooms` 요청으로 바로 시작한다. 5초마다 health를 반복 호출하던 연결 확인 interval도 제거했다.

로그인 화면에서 사용하는 health 요청은 진행 중 Promise를 공유하고 성공 결과를 5초간 재사용한다. 동시에 여러 호출이 들어와도 같은 health 요청을 중복 전송하지 않는다. health 요청 자체에는 자동 재시도를 적용하지 않는다.

HTTP API의 성공 여부와 Socket 연결 상태도 분리했다. 방 목록 API 실패가 Socket 상태를 강제로 오류로 바꾸지 않으며, Socket 상태는 실제 Socket 이벤트가 갱신한다.

### 3.3 공통 HTTP 재시도 정책 제한

자동 재시도 대상을 `GET`과 `HEAD`로 제한하고 최대 재시도 횟수를 1회로 줄였다. `POST`, `PUT`, `PATCH`, `DELETE`는 502·503·504나 네트워크 오류가 발생해도 자동 재전송하지 않는다. 이로써 서버에서는 쓰기가 완료됐지만 응답만 유실된 경우 동일 데이터가 중복 생성될 위험을 줄였다.

재시도 대기 시간은 full jitter를 사용하도록 변경했다. 같은 시점에 실패한 브라우저가 같은 시점에 다시 요청하는 현상을 완화한다.

동일 사용자·동일 URL·동일 파라미터의 `GET` 또는 `HEAD` 요청이 동시에 진행되면 실제 Axios adapter Promise를 공유한다. 같은 endpoint에서 502·503·504가 반복되면 3초간 자동 GET 요청을 제한하는 cooldown도 적용했다.

### 3.4 방 목록과 입장 버튼 개선

방 입장 버튼이 HTTP health 상태에 따라 비활성화되던 조건을 제거했다. 입장 API가 진행 중일 때만 중복 클릭을 막는다. 새 채팅방 생성 버튼도 health 상태와 분리했다.

방 목록 요청은 기존 ref 잠금으로 동시에 두 번 실행되지 않는다. 최초 30초 보정 조회는 기존 동작 계약을 유지하고, 이후 자동 조회는 120초에 사용자별 최대 30초 jitter를 더한 fallback 주기로 변경했다. 화면이 다시 보일 때의 즉시 보정과 Socket 기반 목록 갱신은 유지했다.

### 3.5 Tomcat 설정 환경변수화

고정되어 있던 Tomcat 설정을 환경변수로 주입할 수 있게 변경했다. 환경변수가 없을 때는 기존 로컬 기본값을 그대로 사용한다.

| 환경변수 | 기본값 |
| --- | ---: |
| `TOMCAT_THREADS_MAX` | 10 |
| `TOMCAT_THREADS_MIN_SPARE` | 1 |
| `TOMCAT_ACCEPT_COUNT` | 10 |
| `TOMCAT_MAX_CONNECTIONS` | 50 |

배포 환경에서는 인스턴스 CPU, 메모리, MongoDB와 Redis connection pool을 함께 확인한 뒤 값을 설정해야 한다. 이번 작업은 코드에서 조정 가능하게 만든 것이며 배포 값을 임의로 올리지는 않았다.

### 3.6 프로필 이미지 S3 전달 개선

S3에 프로필 객체가 존재하면 백엔드가 이미지 전체를 byte 배열로 읽지 않고 5분짜리 presigned URL을 생성해 `307 Temporary Redirect`로 전달하도록 변경했다. 브라우저는 S3에서 이미지를 직접 내려받으므로 동시 프로필 이미지 요청이 백엔드 heap과 응답 thread를 점유하는 비용을 줄인다.

S3 object 존재 여부는 먼저 확인한다. S3에 없는 배포 전 로컬 프로필 이미지는 기존 로컬 fallback으로 계속 제공한다. 프로필 이미지 응답에는 5분 cache policy를 적용했다.

S3 변경은 `profiles/` key에만 적용했다. 채팅 첨부파일의 `chat/` key와 로컬 저장 정책은 변경하지 않았다.

| 영역 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 로그인 폼 | health 완료 후 렌더링 | 즉시 렌더링 |
| 로그인 버튼 | health 실패 시 비활성화 | 로그인 요청 진행 중에만 비활성화 |

## 5. 검증 결과

새 테스트나 독립 부하테스트 코드는 만들지 않았다. 저장소에 이미 존재하는 테스트와 빌드만 실행했다.

| 검증 | 결과 |
| --- | --- |
| Frontend `pnpm test` | 테스트 파일 30개, 테스트 120개 모두 통과 |
| Backend `./mvnw test` | 테스트 230개 통과, 실패 0개, 오류 0개, 스킵 8개 |
| Frontend `pnpm build` | Next.js production build 성공 |
| Backend `./mvnw -DskipTests package` | 실행 가능한 Spring Boot JAR 생성 성공 |
| Frontend `pnpm lint` | 오류 0개, 기존 경고 32개 |
| `git diff --check` | 공백 오류 없음 |

백엔드 전체 테스트는 Testcontainers가 필요해 Docker 접근 권한이 있는 환경에서 실행했다. 프론트 테스트는 테스트 내부 CDN 접근이 있어 네트워크 접근이 가능한 환경에서 최종 실행했다.

## 6. 결과 해석

이번 검증은 기능 회귀와 빌드 가능 여부를 확인한 것이다. 공식 After 부하테스트를 실행하지 않았으므로 성공률, P95, P99, 502·504 감소율을 수치로 단정하지 않는다.

코드 수준에서 확실히 줄어든 것은 로그인 전 health gate, 방 목록 전 health 요청, 5초 health polling, 쓰기 요청 자동 재시도, 동시에 발생한 동일 GET, 장기 실행 시 방 목록 polling 빈도, S3 프로필 이미지의 백엔드 전체 byte 중계다.

## 7. 병합 범위

담당자 2의 Socket join, 메시지 입력과 표시, 읽음 처리, 메시지 backend 파일은 변경하지 않았다. 공통 충돌 가능성이 있는 변경은 공통 Axios client와 방 목록 화면으로 제한되어 있으며, 담당자 2 계획의 소유 파일에는 변경이 없다.

현재 변경은 작업 브랜치에만 존재하며 커밋과 push는 수행하지 않았다.
